Module group exam

Modules 5–6: cross-module review

The exam covers Spanning Tree and EtherChannel. If you can answer these cold, Sessions 4 and 5 have landed.

  • Lowest bridge ID is root: priority first (default 32768 plus the VLAN number), then the lowest MAC. Priorities go in steps of 4096 (Session 4).
  • Root port, then designated port, then whatever's left blocks. Ties go to the lower sender bridge ID, then the lower sender port ID (Session 4).
  • 802.1D timers: hello 2 s, forward delay 15 s, max age 20 s, so 30 to 50 seconds to recover. Rapid PVST+ gets that down to about a second (Sessions 4 and 5).
  • PAgP is Cisco's (desirable/auto); LACP is the standard (active/passive). Auto + auto and passive + passive never bundle, and the two protocols never mix (Session 5).
  • Members must match in speed, duplex, mode and VLANs, and trunk settings go on the port-channel (Session 5).

Module 7.1

How DHCPv4 works

DHCPv4 (Dynamic Host Configuration Protocol) hands a host everything it needs to use the network: an IPv4 address and mask, a default gateway, DNS servers, and a domain name. The address is leased, not given: the host borrows it for a set time.

CCNA 1 callback In CCNA 1 you met DORA and learned which of its messages are broadcasts, and you used a 169.254 address as the clue that DHCP had failed. Configuring the server, and ipconfig /release and /renew, were left for CCNA 2. Here they are.

A new client has no address and doesn't know where the server is, so it starts with a broadcast. Four messages follow, often remembered as DORA:

MessageFrom → toWhat it says
DHCPDISCOVERClient → everyone (broadcast)"I need an address. Is there a DHCP server out there?" The client has no address yet, so it sends from 0.0.0.0 to 255.255.255.255.
DHCPOFFERServer → client (usually unicast)"You can have this address, with this mask, gateway and DNS server, for this long." The server reserves the address while it waits.
DHCPREQUESTClient → everyone (broadcast)"I'll take the offer from that server." Broadcast, so any other server that made an offer can withdraw it.
DHCPACKServer → client (usually unicast)"Confirmed. The lease starts now." The client checks nobody else is using the address (with ARP), then uses it.
  • Ports: clients use UDP 68 and servers UDP 67.
  • If no server answers, a Windows client gives itself an APIPA address in 169.254.0.0/16 and keeps trying. A 169.254 address always means "DHCP failed".
  • If the server refuses a request (the address is no longer free, for example), it sends a DHCPNAK, and the client starts again with a discover.

Module 7.1

Leases and renewal

A lease has an expiry time, one day by default on a Cisco router. A client doesn't wait for the end: it renews well before.

WhenWhat the client does
50% of the lease (T1)Sends a DHCPREQUEST straight to the server that gave it the lease (unicast). The server answers with a DHCPACK, and the lease starts over. No discover, no offer.
87.5% of the lease (T2)If its own server never answered, it broadcasts a DHCPREQUEST, so any server can renew it.
Lease expiresIt stops using the address and starts over with a DHCPDISCOVER.

A shorter lease frees unused addresses faster, which suits a busy guest network; a longer one means less DHCP traffic. On a Windows PC, ipconfig /release gives the lease back and ipconfig /renew asks for one, which is how you test DHCP without waiting.

Configure a Cisco router as a DHCPv4 server

A Cisco IOS router can be a full DHCP server. Two pieces of configuration: the addresses it must never hand out, and a pool for each subnet it serves.

HQ's design rule decides the pools: in each /24, .1–.100 are for static devices and are excluded, and the rest is leased. VLAN 30 is a /26, so its excluded block is smaller.

Module 7.2

DHCP relay: carrying the shout across the door

A DHCPDISCOVER is a broadcast, and routers don't forward broadcasts. A PC in VLAN 30 shouts, D1 hears it on its Vlan30 SVI, and the message stops there. R1, the server, never hears it. A DHCP relay agent fixes that.

A relay agent is an interface that listens for DHCP broadcasts from clients and forwards each one as a unicast to a server address it has been given. On a Cisco router or Layer 3 switch, that's one command on the interface where the clients' broadcasts arrive: ip helper-address.

D1 · one helper on each SVI
D1# configure terminal D1(config)# interface vlan 10 D1(config-if)# ip helper-address 10.0.0.9 D1(config-if)# exit D1(config)# interface vlan 30 D1(config-if)# ip helper-address 10.0.0.9 D1(config-if)# exit ! No VLAN 99 client until Session 10, but the relay is ready with the pool. D1(config)# interface vlan 99 D1(config-if)# ip helper-address 10.0.0.9 D1(config-if)# end D1# copy running-config startup-config
  • On the SVI, not on the link to R1. The helper goes where the broadcasts arrive. On G1/0/24 it would do nothing for anyone.
  • One helper per VLAN. A VLAN without one gets nothing.
  • Why 10.0.0.9? It's R1's address on the link to D1, directly connected, so it needs no route. R1's other address, 10.0.0.1, faces R2: if that link failed, HQ's DHCP would fail with it, even though nothing between HQ and R1 broke. Point the helper at the server's nearest door.
  • It relays more than DHCP. By default, ip helper-address forwards broadcasts for eight UDP services, including DNS (53), TFTP (69) and NetBIOS (137, 138), as well as DHCP (67, 68).

The giaddr: two jobs

When D1 relays, it writes the address of the interface the broadcast arrived on, 192.168.10.1, into the message's giaddr (gateway IP address) field. R1 uses it twice:

  • To choose the pool. 192.168.10.1 is inside 192.168.10.0/24, so the offer comes from HQ-VLAN10. The same request relayed by Vlan30 would get a VLAN 30 address.
  • As the address to reply to. R1 sends the offer to 192.168.10.1. So R1 needs a route back to every giaddr.
R1 · the routes back to every giaddr (from Session 3)
R1# show ip route static ... S 192.168.10.0/24 [1/0] via 10.0.0.10 S 192.168.20.0/24 [1/0] via 10.0.0.2 192.168.30.0/26 is subnetted, 1 subnets S 192.168.30.0 [1/0] via 10.0.0.10 S 192.168.99.0/24 [1/0] via 10.0.0.10

R1 already had these from Session 3. Without the VLAN 30 route, R1 would hear PC-D, answer, and drop the answer: it has no default route until Session 11.

Check the relay on D1

D1 · is the helper set?
D1# show ip interface vlan 10 Vlan10 is up, line protocol is up Internet address is 192.168.10.1/24 Broadcast address is 255.255.255.255 Address determined by setup command MTU is 1500 bytes Helper address is 10.0.0.9 ...

On real IOS, an SVI without a relay says Helper address is not set.

Module 7.2

The direct case: R2 serves its own LAN

No relay is needed when the server sits on the client's own subnet. R2's G0/0/1 is the gateway for the Shipping LAN, so its clients' broadcasts reach R2 directly.

R2 · a pool for its own LAN
R2# configure terminal R2(config)# ip dhcp excluded-address 192.168.20.1 192.168.20.100 R2(config)# ip dhcp pool SHIPPING-VLAN20 R2(dhcp-config)# network 192.168.20.0 255.255.255.0 R2(dhcp-config)# default-router 192.168.20.1 R2(dhcp-config)# dns-server 192.168.20.100 R2(dhcp-config)# domain-name it141.example R2(dhcp-config)# end R2# copy running-config startup-config

The excluded block protects R2's own .1, S3's management address .2, and SRV1 at .100.

Module 7.3

A router as a DHCPv4 client

Routers usually have static addresses, but the interface facing an internet provider often doesn't: the provider leases it. A Cisco router interface, and the internet port of a home router, can both be DHCP clients.

A Cisco router interface

One interface command, ip address dhcp, in place of a static address. The router then runs DORA on that link like any PC.

Scratch router · G0/0/0 leases an address from R2
Router(config)# interface g0/0/0 Router(config-if)# ip address dhcp ! Router interfaces start shut. Without this, nothing is ever sent. Router(config-if)# no shutdown Router(config-if)# end %DHCP-6-ADDRESS_ASSIGN: Interface GigabitEthernet0/0/0 assigned DHCP address 192.168.20.103, mask 255.255.255.0, hostname Router
Scratch router · proof the address came from DHCP
Router# show ip interface brief Interface IP-Address OK? Method Status Protocol GigabitEthernet0/0/0 192.168.20.103 YES DHCP up up GigabitEthernet0/0/1 unassigned YES unset administratively down down Router# show ip interface g0/0/0 GigabitEthernet0/0/0 is up, line protocol is up Internet address is 192.168.20.103/24 Broadcast address is 255.255.255.255 Address determined by DHCP ...
  • The Method column says DHCP, not manual.
  • On real IOS, the router also takes a default route from the pool's default-router, with administrative distance 254, so any static default typed later wins. (Beyond Module 7; Session 11 explains administrative distance.)
  • In a real network this is the interface facing an internet provider. Here R2 plays the provider.

A home router's internet port

A home wireless router has two sides. Its internet port is a DHCP client: home routers ship set to lease an address from whatever they're plugged into, so a customer can connect one to a modem and go. Its LAN side is a DHCP server for the home, handing out 192.168.0.x behind NAT. The two ranges never mix.

In Packet Tracer the setting is in the router's GUI tab, under Setup → Basic Setup → Internet Setup: Automatic Configuration - DHCP. The Status page should show the address it leased. Menu names can differ slightly between Packet Tracer versions. The home router is on S3 F0/3 at the Shipping site, so R2 is its provider.

One cable, two very different devices Plugged in by its internet port, the home router is a well-behaved client of R2. Plugged in by a LAN port, its own DHCP server starts answering the Shipping LAN, and PC-B could end up with a 192.168.0.x address. That's a rogue DHCP server, and stopping one is Session 9's job.

The method: follow the request

A 169.254 address says only that no offer came back. Walk the path in the order the request travels:

  1. Client: is it set to DHCP, and is its switch port in the right VLAN?
  2. Relay (HQ only): does that VLAN's SVI have the right helper?
  3. Did the server hear it? R1's DHCPDISCOVER counter, before and after an ipconfig /renew. If it didn't move, go back to the relay.
  4. Did the server answer? If DISCOVER moved but OFFER didn't, look at the pools.
  5. Did the answer get back? If OFFER moved and the client still has nothing, check R1's route to the giaddr.
  6. Address, but stuck in its own subnet? Then it's the options (gateway, mask), not the lease.

If Packet Tracer's counters don't move, use Simulation mode with the DHCP filter instead: you can see which leg the request stops on.

Watch for this

Common Module 7 mistakes

Most DHCP faults are a missing relay, a pool that disagrees with the subnet, or an exclusion that leaves out the wrong addresses.

1 · The helper on the wrong interface

On D1's link to R1 instead of the SVIs. The helper goes where the clients' broadcasts arrive.

2 · The gateway is the server

default-router 10.0.0.9. The default router is the gateway the client uses, D1's SVI for that VLAN. The server's address has nothing to do with it.

3 · The /26 typed as a /24

VLAN 30's pool with 255.255.255.0. PC-D works today, and later clients get addresses outside its subnet. Check the mask in ipconfig.

4 · Exclusions after the pool

If a client asks between the pool and the exclusion, it can be handed a static device's address. Exclude first.

5 · Forgetting to renew

A fixed pool doesn't reach clients that already have a lease. ipconfig /renew after every pool change.

6 · Reading 169.254 as "the network is down"

It only means no DHCP offer came back. Ping the gateway from a static host: if that works, the problem is DHCP.

Recurring segment

The Ticket

Turn it into steps before you open the answer.

Ticket #141-06 · Priority: high · From: Logistics

The new hire at the Logistics desk can't get onto anything. Their PC says something about "APIPA". The Front Desk new hire, who started the same day, is fine. We didn't change anything.

One way to break it down
  1. "APIPA" means a 169.254 address: no DHCP offer reached the PC. The network itself may be fine.
  2. Front Desk works, Logistics doesn't. Same server, different VLAN. So R1's pools in general are fine, and the fault is something VLAN 30 has on its own: its access port, its relay, its pool, or R1's route back to it.
  3. Check the PC first: set to DHCP? Then its port: show vlan brief on S2, Fa0/11 should be in VLAN 30.
  4. Check the relay: show ip interface vlan 30 on D1 should show Helper address is 10.0.0.9.
  5. Check the server heard it: show ip dhcp server statistics on R1 before and after ipconfig /renew on the PC. DISCOVER up but OFFER not: the VLAN 30 pool (show running-config | section dhcp). Both up: R1's route to 192.168.30.0/26.
  6. Verify: the PC gets 192.168.30.x with mask 255.255.255.192 and gateway 192.168.30.1, then reaches www.it141.example.

Broadcasts

Which DORA messages are broadcasts?

A client has held 192.168.10.101 for 12 hours of its one-day lease, and has been running the whole time. Which message does it send now, and is it a broadcast? Which messages are broadcasts in a brand-new exchange?

Show answer

Twelve hours is half the lease, which is T1, so it renews with a unicast DHCPREQUEST straight to the server. Only a client with no address (or one whose renewals all failed) starts over with a broadcast DHCPDISCOVER. In a brand-new exchange, the DISCOVER and the REQUEST are the broadcasts.

Relay

Which pool?

PC-D in VLAN 30 asks for an address. D1 relays it to R1, which has pools for VLANs 10, 30 and 99. How does R1 know to use the VLAN 30 pool?

Show answer

From the giaddr. D1 relayed the request from its Vlan30 SVI, so it wrote 192.168.30.1 in the giaddr field. That address is inside the HQ-VLAN30 pool's network, 192.168.30.0/26, so R1 offers a VLAN 30 address, and sends the offer back to 192.168.30.1.

Counting

How many leases?

How many addresses can R1 lease in VLAN 30, and why isn't it 62?

Show answer

The /26 has 62 usable addresses, .1 to .62. .1–.9 are excluded, which leaves .10 to .62: 53 addresses. That's enough for CCNA 1's "LAN-C, 50 users".

Exclusions

Why didn't PC-D keep .9?

PC-D had the static address 192.168.30.9. After moving to DHCP it got 192.168.30.10. Why not .9 again?

Show answer

.9 is inside the excluded range, .1–.9, so the server will never lease it. The first address it can lease is .10. The rule works both ways: static devices live in the excluded block, and leased ones never land there.

Direct vs relay

Why no helper at R2?

PC-B gets its address from R2 with no ip helper-address anywhere. Why does HQ need one and Shipping doesn't?

Show answer

R2's G0/0/1 is 192.168.20.1, on PC-B's own subnet, so PC-B's broadcast reaches R2 directly. R1 isn't on any HQ VLAN: the broadcasts stop at D1, so D1 has to relay them.
