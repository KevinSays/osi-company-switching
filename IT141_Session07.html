Midterm

Cross-module review

If you can answer these cold, Sessions 1–6 have landed. All of them come straight out of material already covered: this is recall, not new content.

  • Access or trunk, and which VLAN is native. An access port carries one VLAN untagged; a trunk carries many, tagged with 802.1Q, except the native VLAN, which crosses untagged and must match at both ends. DTP's auto + auto never makes a trunk (Session 2).
  • Every host's gateway is the router address in its own VLAN. A subinterface on a router-on-a-stick, or an SVI on a Layer 3 switch with ip routing on. A host pointed at another VLAN's .1 reaches nothing off its subnet (Session 3).
  • Lowest bridge ID is root; then root ports, then designated ports; whatever's left blocks. Priority first (32768 plus the VLAN number by default), then the lowest MAC (Session 4).
  • EtherChannel members must match in speed, duplex, mode and VLANs. LACP is active/passive, PAgP is desirable/auto, and the two never mix (Session 5).
  • DHCP broadcasts stop at the router. ip helper-address on the interface where the clients' broadcasts arrive relays them; the server picks the pool from the giaddr. A 169.254 address means no offer came back (Session 6).

Module 8.1

Three ways to a global address

A router's IPv6 addresses are typed in by hand with ipv6 address, and so are a few servers', like SRV1's. Typing a 128-bit address into every PC is slow and easy to get wrong, so hosts are normally set to get their IPv6 configuration automatically. Two things happen when they do.

CCNA 1 callback In CCNA 1 you met the three methods by name: SLAAC only, SLAAC with stateless DHCPv6, and stateful DHCPv6. You learned that even with stateful DHCPv6, the default gateway still comes from the router's advertisement. The RA flags and the commands that set them were left for CCNA 2. Here they are.
  • The link-local address comes first, on its own. As soon as the interface is up, the host makes an fe80:: address. It needs no router and no server. In ipconfig a Windows host shows it with a zone ID (also called a scope ID) on the end, such as %11: the operating system's label for which interface the address belongs to.
  • The global address depends on the router. An IPv6 router sends Router Advertisements (RAs), ICMPv6 messages that carry the LAN's prefix and the router's own link-local address as the gateway. With no router on the segment, a host has a link-local address and nothing more.

Every RA carries three flags. Together they tell the host which method to use. The host's operating system makes the final decision, but hosts normally follow them.

FlagNameSet to 1, it meansDefault on a Cisco router
AAddress AutoconfigurationBuild your own global address from the prefix in this RA (SLAAC)1
OOther ConfigurationGet other information, such as DNS servers, from a stateless DHCPv6 server0
MManaged Address ConfigurationGet your address from a stateful DHCPv6 server0
MethodFlagsGlobal address fromDNS and other information fromDefault gateway from
1 · SLAAC onlyA=1, O=0, M=0The host, using the RA's prefixNothing by DHCPv6. (An RA can carry a DNS server, but IOS doesn't add one by default.)Always the RA: the router's link-local address
2 · SLAAC + stateless DHCPv6A=1, O=1, M=0The host, using the RA's prefixA stateless DHCPv6 server
3 · Stateful DHCPv6A=0, M=1A stateful DHCPv6 serverThe same DHCPv6 server
The one that's different from DHCPv4 DHCPv6 has no default-router option. However a host gets its address, its gateway is the source address of the RA: the router's link-local address. That's why every IPv6 gateway on this site is fe80::1 or fe80::2, never a global address.

Module 8.2

SLAAC: the sign on the wall

SLAAC (Stateless Address Autoconfiguration) lets a host build its own global address with no DHCPv6 server at all. It's stateless: nothing keeps a list of which addresses are in use. It's how PC-C and PC-D have had IPv6 addresses ever since they joined the network.

Router solicitations and advertisements

  • The router advertises on its own, every 200 seconds on Cisco IOS by default, to the all-nodes multicast group ff02::1.
  • A host that has just booted doesn't wait. It sends a Router Solicitation (RS) to the all-routers group ff02::2, and the router answers at once with an RA.
  • Only a router sends RAs, and a Cisco router is only a router for IPv6 after ipv6 unicast-routing. That command joins its interfaces to ff02::2 and starts the RAs, with A=1, O=0 and M=0: SLAAC only, by default.
R2 · default router advertisements on the Shipping LAN
R2# show ipv6 interface g0/0/1 GigabitEthernet0/0/1 is up, line protocol is up IPv6 is enabled, link-local address is FE80::2 No Virtual link-local address(es): Global unicast address(es): 2001:DB8:ACAD:20::1, subnet is 2001:DB8:ACAD:20::/64 Joined group address(es): FF02::1 FF02::2 FF02::1:FF00:1 FF02::1:FF00:2 MTU is 1500 bytes ... ND DAD is enabled, number of DAD attempts: 1 ND reachable time is 30000 milliseconds (using 30000) ND router advertisements are sent every 200 seconds ND router advertisements live for 1800 seconds ND advertised default router preference is Medium Hosts use stateless autoconfig for addresses.
  • FF02::2 is there because ipv6 unicast-routing is on. It has been on R2 since CCNA 1; nothing was typed today.
  • Four groups: all-nodes FF02::1, all-routers FF02::2, and one solicited-node group per unicast address: FF02::1:FF00:1 for the global ::1, and FF02::1:FF00:2 for the link-local fe80::2. Each is FF02::1:FF plus the address's last 24 bits.
  • "Hosts use stateless autoconfig for addresses." The default flags: A=1, O=0, M=0, so SLAAC only.
  • "live for 1800 seconds" is the router lifetime: how long a host keeps R2 as its gateway without hearing another RA. It's how the RA, not DHCP, keeps the gateway alive.

Building the interface ID

The RA supplies the first 64 bits, the prefix. The host makes the last 64, the interface ID, in one of two ways:

MethodHowWho uses it
EUI-64The 48-bit MAC, split in half with fffe in the middle, and the seventh bit flippedCisco routers, for their own link-local addresses; many Packet Tracer hosts
Random64 random bits, chosen by the operating systemWindows by default (NetAcad's example is Windows 10). It keeps the MAC out of the address, for privacy.

Until today PC-B had a static IPv6 address, :20::10. Set its IPv6 configuration to automatic and it takes R2's offer. The MAC addresses on this page are made up, and so are the DUIDs and leased addresses further down.

PC-B · IPv6 set to automatic: SLAAC only
C:\> ipconfig /all FastEthernet0 Connection:(default port) Connection-specific DNS Suffix..: it141.example Physical Address................: 0060.70AA.0020 Link-local IPv6 Address.........: FE80::260:70FF:FEAA:20 IPv6 Address....................: 2001:DB8:ACAD:20:260:70FF:FEAA:20 IPv4 Address....................: 192.168.20.102 Subnet Mask.....................: 255.255.255.0 Default Gateway.................: FE80::2 192.168.20.1 DHCP Servers....................: 192.168.20.1 DHCPv6 IAID.....................: DHCPv6 Client DUID..............: ... DNS Servers.....................: :: 192.168.20.100 ...
  • The global address is R2's /64 prefix plus an interface ID PC-B made itself, here by EUI-64: 0060.70AA.0020 → 0060:70FF:FEAA:0020 → flip the seventh bit → 260:70FF:FEAA:20. That's why the global and link-local addresses end the same way. A real Windows PC would show a random-looking ending instead.
  • The IPv6 gateway is FE80::2, the source address of R2's RAs, not R2's global address.
  • No IPv6 DNS server (::). An RA can carry one, but IOS doesn't add it unless configured to (beyond this course). PC-B still resolves names through its IPv4 DNS server from Session 6. That gap is what stateless DHCPv6 fills next.

Duplicate address detection

Before using an address it made itself, a host checks that no one else has it. This is DAD: the host sends an ICMPv6 Neighbor Solicitation (NS) for its own new address, to that address's solicited-node multicast group (ff02::1:ff plus the address's last 24 bits). If a Neighbor Advertisement (NA) comes back, someone already owns it, and the host must pick another interface ID. Silence means the address is free. With 264 possible interface IDs, a clash is very unlikely, but most operating systems run DAD on every unicast address anyway, however it was configured.

Module 8.3

How DHCPv6 works

When the RA says O=1 or M=1, the host still starts with RS and RA, then talks to a DHCPv6 server. DHCPv6 has its own messages, and they don't map one-to-one onto DORA.

MessageFrom → toWhat it says
SOLICITClient → ff02::1:2"Is there a DHCPv6 server out there?" (like DHCPDISCOVER)
ADVERTISEServer → client"I can serve you." (like DHCPOFFER)
REQUESTClient → ff02::1:2, naming the server it chose"Send me the address and settings." (like DHCPREQUEST)
REPLYServer → clientThe address, if stateful, plus DNS servers and the domain name (like DHCPACK)
INFORMATION-REQUESTClient → ff02::1:2Stateless only: "I have an address; just send me the other settings." The server answers with a REPLY.
  • Ports: client-to-server messages go to UDP 547, server-to-client to UDP 546. (DHCPv4 used 67 and 68.)
  • No broadcasts. IPv6 has none. The client uses its link-local address and a multicast group.
  • Stateless vs stateful is about what the server remembers. A stateless server hands out settings and keeps no record. A stateful server leases addresses, so it keeps a binding for every client, just like a DHCPv4 server.
  • The four-message exchange is how a host gets an address. A stateless host, which only needs the settings, can do it in two: INFORMATION-REQUEST and REPLY. Either way, a stateless server sends settings and keeps no binding.

Module 8.4

Configure a stateless DHCPv6 server

PC-B builds its own address with SLAAC, but its IPv6 settings list no DNS server. A stateless DHCPv6 server on R2 fills that gap, and the address stays exactly as it is.

Five steps on R2:

  1. ipv6 unicast-routing, on since CCNA 1
  2. Create a pool with ipv6 dhcp pool
  3. Give it the options: dns-server and domain-name. No addresses: a stateless pool has none.
  4. Bind the pool to the LAN interface with ipv6 dhcp server
  5. Set the O flag on that interface with ipv6 nd other-config-flag. The A flag stays 1, so hosts keep using SLAAC.
R2 · a stateless DHCPv6 server for Shipping
R2# configure terminal R2(config)# ipv6 dhcp pool SHIPPING-STATELESS R2(config-dhcpv6)# dns-server 2001:db8:acad:20::100 R2(config-dhcpv6)# domain-name it141.example R2(config-dhcpv6)# exit R2(config)# interface g0/0/1 R2(config-if)# ipv6 dhcp server SHIPPING-STATELESS ! ! Set the O flag: addresses by SLAAC, everything else from DHCPv6 R2(config-if)# ipv6 nd other-config-flag R2(config-if)# end
  • No address prefix line. A stateless pool has options only.
  • The pool does nothing until it's bound with ipv6 dhcp server. That's a real difference from Session 6, where a DHCPv4 pool matched its clients by subnet with no interface command at all.
  • The O flag is what makes hosts ask. A bound pool with no O flag gets no requests; an O flag with no bound pool gets requests nobody answers. It takes both halves.
  • ipv6 unicast-routing is NetAcad's first step. It's already on R2, so it isn't typed again.
R2 · the O flag is on and the pool is bound
R2# show ipv6 interface g0/0/1 ... ND advertised default router preference is Medium Hosts use stateless autoconfig for addresses. Hosts use DHCP to obtain other configuration. R2# show ipv6 dhcp interface g0/0/1 GigabitEthernet0/0/1 is in server mode Using pool: SHIPPING-STATELESS Preference value: 0 Hint from client: ignored Rapid-Commit: disabled R2# show ipv6 dhcp pool DHCPv6 pool: SHIPPING-STATELESS DNS server: 2001:DB8:ACAD:20::100 Domain name: it141.example Active clients: 0 R2# show ipv6 dhcp binding R2#
PC-B · the same SLAAC address, now with an IPv6 DNS server
C:\> ipconfig /all ... IPv6 Address....................: 2001:DB8:ACAD:20:260:70FF:FEAA:20 ... Default Gateway.................: FE80::2 192.168.20.1 DHCPv6 Client DUID..............: 00-01-00-01-A1-B2-C3-D4-00-60-70-AA-00-20 DNS Servers.....................: 2001:DB8:ACAD:20::100 192.168.20.100 ...
  • One new line on R2. "Stateless autoconfig for addresses" stays, because A is still 1; the O flag adds "DHCP to obtain other configuration".
  • PC-B's address didn't change. Only its DNS servers did. (The DNS suffix is no proof: PC-B already had it141.example from DHCPv4.)
  • An empty show ipv6 dhcp binding is the right answer. A stateless server keeps no record of who asked; Active clients: 0 says the same. That's what stateless means.
  • The DUID (DHCP unique identifier) is how a DHCPv6 client identifies itself. It usually contains a MAC address, but it isn't one.

Module 8.4

Configure a stateful DHCPv6 server

A stateful server leases the addresses too, and keeps a record of who has which. That's what an administrator wants when they need to know exactly which host had an address at a given time.

The same five steps, with three differences:

  • The pool has addresses: an address prefix line.
  • The M flag goes to 1: ipv6 nd managed-config-flag.
  • The A flag goes to 0: ipv6 nd prefix default no-autoconfig. Without this, hosts follow both instructions and end up with two global addresses, one they made and one they leased.

NetAcad's own DHCPv6 lab leases from a longer prefix inside the LAN's /64, and so does R2 here: 2001:db8:acad:20:aaaa::/80. The RA still advertises the /64, so the subnet doesn't change, but every lease starts …:20:aaaa:. IOS DHCPv6 has no excluded-address command, so this is how leases are kept away from R2's ::1 and SRV1's ::100: the IPv6 version of Session 6's "statics below .100" rule.

R2 · switching Shipping to stateful DHCPv6
R2# configure terminal R2(config)# ipv6 dhcp pool SHIPPING-STATEFUL R2(config-dhcpv6)# address prefix 2001:db8:acad:20:aaaa::/80 R2(config-dhcpv6)# dns-server 2001:db8:acad:20::100 R2(config-dhcpv6)# domain-name it141.example R2(config-dhcpv6)# exit R2(config)# interface g0/0/1 ! ! One DHCPv6 pool per interface: unbind the stateless pool, bind the stateful one R2(config-if)# no ipv6 dhcp server SHIPPING-STATELESS R2(config-if)# ipv6 dhcp server SHIPPING-STATEFUL ! ! M flag on: get your address from DHCPv6 R2(config-if)# ipv6 nd managed-config-flag ! ! A flag off: don't build a SLAAC address from this prefix R2(config-if)# ipv6 nd prefix default no-autoconfig ! ! Optional: O adds nothing once M is set R2(config-if)# no ipv6 nd other-config-flag R2(config-if)# end
  • Three flags, three lines: M=1, A=0, and (optionally) O=0, which makes the flags read A=0, O=0, M=1, as in the module.
  • Forgetting no-autoconfig is the classic error. The host then builds a SLAAC address and leases one.
  • No lifetime given, so IOS uses its own: the output below shows 1 day preferred, 2 days valid.
R2 · the M flag is on
R2# show ipv6 interface g0/0/1 ... ND advertised default router preference is Medium Hosts use DHCP to obtain routable addresses.

PC-B doesn't drop its SLAAC address the moment the flags change: with A=0 it stops being refreshed and ages out. To see the clean result straight away, restart PC-B's connection: in Packet Tracer, set IPv6 to Static and back to Automatic; on a real Windows PC, disable and re-enable the network adapter. (ipconfig /renew6 alone would lease the new address but leave the old SLAAC one in place for now.)

CCNA 1 callback The gateway is still FE80::2, and it came from R2's RA, not from DHCPv6. A fully stateful host still learns its gateway from the router's advertisement, exactly as CCNA 1 said. That's why R2 keeps sending RAs, with M=1.

  • T1 and T2 are 50% and 80% of the preferred lifetime: the same idea as Session 6, but T2 isn't DHCPv4's 87.5%.

Module 8.4

A router as a DHCPv6 client

A Cisco router can be a DHCPv6 server, a relay agent, or a client. As a client, its interface takes its IPv6 configuration from a server on the link, just as a PC does. In Session 6 a scratch router leased an IPv4 address from R2; here the same router does it for IPv6.

A client interface needs a link-local address before it can send anything. A router makes one automatically when the interface gets a global address; with no global address yet, ipv6 enable makes one on its own, using EUI-64.

The scratch router plugs into S3 F0/4 on the Shipping LAN, as in Session 6.

Scratch router · a stateless DHCPv6 client on the Shipping LAN
Router(config)# ipv6 unicast-routing Router(config)# interface g0/0/0 ! ! Creates the link-local address (EUI-64) with no global address yet Router(config-if)# ipv6 enable Router(config-if)# ipv6 address autoconfig Router(config-if)# no shutdown Router(config-if)# end Router# show ipv6 interface brief GigabitEthernet0/0/0 [up/up] FE80::250:FFF:FE12:4 2001:DB8:ACAD:20:250:FFF:FE12:4 GigabitEthernet0/0/1 [administratively down/down] unassigned ... A host doesn't give up a leased address just because the M flag went away: it keeps it until it's released or expires. After PC-B renews, it's back on its EUI-64 SLAAC address, with R2's DNS server.

Module 8.4

DHCPv6 relay

A SOLICIT goes to ff02::1:2, a link-local multicast group, so it never leaves the LAN. A DHCPv6 server on another network needs a relay agent, the same job ip helper-address did for DHCPv4 in Session 6.

What if HQ's VLAN 10 got stateful DHCPv6 from R1, the way it gets DHCPv4? It isn't configured; HQ stays on plain SLAAC all term. VLAN 10's hosts hear D1's RAs, so D1 is where both the flags and the relay go.

D1 · what-if: flags and relay on the clients' SVI (not configured on HQ)
D1(config)# interface vlan 10 D1(config-if)# ipv6 nd managed-config-flag D1(config-if)# ipv6 nd prefix default no-autoconfig D1(config-if)# ipv6 dhcp relay destination 2001:db8:acad:ff03::1 D1(config-if)# end D1# show ipv6 dhcp interface vlan 10 Vlan10 is in relay mode Relay destinations: 2001:DB8:ACAD:FF03::1
R1 · what-if: the pool, bound where the relayed requests arrive
R1(config)# ipv6 dhcp pool HQ-VLAN10-V6 R1(config-dhcpv6)# address prefix 2001:db8:acad:10:aaaa::/80 R1(config-dhcpv6)# dns-server 2001:db8:acad:20::100 R1(config-dhcpv6)# domain-name it141.example R1(config-dhcpv6)# exit R1(config)# interface g0/0/1 R1(config-if)# ipv6 dhcp server HQ-VLAN10-V6
  • The relay goes on the interface facing the clients, the same place as Session 6's ip helper-address.
  • Why ff03::1? It's R1's end of the D1 link, directly connected: the IPv6 twin of Session 6's 10.0.0.9. It's a global address, so no exit interface is needed. Aimed at R1's link-local address instead, the command must name the interface too: ipv6 dhcp relay destination fe80::1 g1/0/24.
  • The flags go on D1, not R1. They belong to the router whose RAs the hosts hear. A relay with no M or O flag in the RA relays nothing, because no host asks.
  • R1's pool is bound to G0/0/1, the interface the relayed requests arrive on.

Module 9.1

First-hop redundancy: one gateway is one point of failure

Every host has one IPv4 default gateway. At HQ that's D1: 192.168.10.1 for Front Desk and 192.168.30.1 for Logistics. If D1 fails, those hosts can still reach each other inside their own VLAN, and nothing else. A second router on the same VLANs wouldn't help on its own, because no host would know to use it.

The fix is a virtual router. Two or more routers share one IP address and one MAC address, and hosts use that shared address as their gateway. One router does the forwarding; the others wait. When a host ARPs for the gateway, it gets the virtual MAC, so it never knows, or cares, which physical router is answering. That ability to recover from a failed gateway is first-hop redundancy, and the protocols that run it are FHRPs (first-hop redundancy protocols).

When the forwarding router fails:

  1. The standby router stops hearing hello messages from it.
  2. The standby router takes over the forwarding role.
  3. It takes over the virtual IP and the virtual MAC, so the hosts' ARP caches are still right, and they carry on with no change.
FHRPWhoseWhat to know
HSRP (Hot Standby Router Protocol)CiscoOne active router forwards and one standby waits. HSRP for IPv6 does the same for IPv6, with a virtual link-local gateway.
VRRPv2 (Virtual Router Redundancy Protocol)Open standardIPv4 only. One virtual router master forwards; the others are backups.
VRRPv3Open standardIPv4 and IPv6; works between vendors and scales better than v2
GLBP (Gateway Load Balancing Protocol)CiscoRedundancy and load balancing: every router in the group forwards some of the traffic. GLBP for IPv6 does the same for IPv6.
IRDP (ICMP Router Discovery Protocol)RFC 1256Legacy: hosts discover routers themselves. You'll only meet it as a name.

Module 9.2

HSRP: the backup front door

HSRP picks one active router to forward for the virtual address and one standby router to watch it and take over. Any others in the group just listen.

Who becomes active: priority and preemption

  • Highest priority wins. The default is 100, and the range is 0–255. Set it with standby priority.
  • On a tie, the highest IPv4 address wins. Leaving the choice to that is leaving it to chance: set the priority.
  • Once a router is active, it stays active, even if a router with a higher priority comes online later. With no preemption, the router that boots first simply wins.
  • standby preempt lets a higher-priority router take the active role back. It only works on priority: a router with the same priority and a higher address won't preempt.

States and timers

StateWhat the router is doing
InitialJust started: HSRP was configured, or the interface just came up
LearnDoesn't know the virtual IP yet and hasn't heard the active router. Waiting.
ListenKnows the virtual IP, but is neither active nor standby. Listens to the hellos.
SpeakSends hellos and takes part in the election
StandbyNext in line. Sends hellos and watches the active router.
ActiveForwards traffic sent to the virtual IP and MAC
  • Hello every 3 seconds to the group's multicast address, from the active and the standby router.
  • Hold time 10 seconds. If the standby hears nothing from the active router for 10 seconds, it becomes active.
  • Both can be shortened for faster failover, but not below 1 second for hellos or 4 for the hold time: shorter timers cost CPU and can cause needless changes of role.

Module 9.2

Failover: the front door closes

Back to the cold open: D1 goes dark. With one gateway, Front Desk would be cut off until someone fixed it. With HSRP, the gateway is back in about ten seconds. In this what-if that gets Front Desk as far as D2 can reach: the other HQ VLAN, but not off-site.

D1 loses power. D2 hears no hello for the 10-second hold time, and takes over both groups:

D2 · about 10 seconds after D1 lost power
%HSRP-5-STATECHANGE: Vlan10 Grp 10 state Standby -> Active %HSRP-5-STATECHANGE: Vlan30 Grp 30 state Standby -> Active D2# show standby brief P indicates configured to preempt. | Interface Grp Pri P State Active Standby Virtual IP Vl10 10 100 Active local unknown 192.168.10.1 Vl30 30 100 Active local unknown 192.168.30.1
PC-C · pinging PC-D across the failover
C:\> ping -t 192.168.30.10 Reply from 192.168.30.10: bytes=32 time<1ms TTL=127 Reply from 192.168.30.10: bytes=32 time<1ms TTL=127 Request timed out. Request timed out. Request timed out. Reply from 192.168.30.10: bytes=32 time<1ms TTL=127 ...
  • A few seconds of loss, then replies again. The gap is about the hold time, not instant.
  • PC-C's ARP entry doesn't change. D2 now answers for the same virtual MAC, and tells the switches where that MAC lives now. That's NetAcad's "no disruption" point, minus a few lost packets.
  • Standby unknown means there's no backup any more: D2 is on its own.
  • S1 and S2 also lose their root bridge, so STP reconverges at the same time: quickly, with Rapid PVST+, and S1 becomes root as the secondary.
  • Why the test is PC-D, not SRV1: D2 can route between its own two SVIs, but in this what-if it has no way off-site.

D1 comes back

When D1 is powered back on, it hears D2's hellos, sees that its own priority (150) is higher than D2's (100), and, because it's set to preempt, takes the active role back. D2 drops back to standby. show standby brief on D1 looks just like it did before the failure. Without standby 10 preempt, D1 would sit as standby until D2 failed.

Why the whole of D1, and not one SVI If only D1's Vlan10 SVI went down, VLAN 10 would move to D2 while VLAN 30 stayed on D1. Replies from VLAN 30 to VLAN 10 would then reach D1, which no longer has a VLAN 10 interface, and would bounce between D1 and R1 until they expired. Real networks prevent that with HSRP interface tracking, which is beyond this course. Failing the whole switch keeps the example clean.

Watch for this

Common Module 8 and 9 mistakes

Most Module 8 faults are an RA flag that says one thing while the server says another. Most HSRP faults are a router that's ready to take over but never does.

1 · A pool with no ipv6 dhcp server

The O flag is set, PC-B asks, and nobody answers: its IPv6 DNS stays ::. A DHCPv6 pool has to be bound to the interface. show ipv6 dhcp interface g0/0/1 should say in server mode and name the pool.

2 · A bound pool with no O flag

The server is ready, but the RA never tells hosts to ask. show ipv6 interface g0/0/1 has no "Hosts use DHCP to obtain other configuration" line.

3 · M without no-autoconfig

Hosts end up with two global addresses, one built and one leased. The trap: show ipv6 interface still says "Hosts use DHCP to obtain routable addresses", because that line follows the M flag, not A. Look for the ipv6 nd prefix default no-autoconfig line in show running-config interface g0/0/1.

4 · Flags on the wrong router

The flags belong to the router whose RAs the hosts hear: R2 for Shipping, D1 for HQ. Setting them on a DHCPv6 server on another network changes nothing for the hosts.

5 · Looking for a gateway in DHCPv6

There's no default-router in a DHCPv6 pool. The IPv6 gateway always comes from the RA. If a host has no IPv6 gateway, check the router's RAs, starting with ipv6 unicast-routing (FF02::2 missing from show ipv6 interface).

6 · Expecting a stateless server to list bindings

An empty show ipv6 dhcp binding on a stateless server is correct. Check the host's ipconfig /all instead.

7 · Priority without preempt

D1 has priority 150, fails, and comes back as standby, while D2 stays active. show standby brief on D1 has no P. Add standby 10 preempt.

8 · Equal priorities, and a surprise after a power cut

With no priority set, the router that comes up first stays active. After both restart together, the highest address wins: D2 (.3). Both show Pri 100. Set the priority, rather than leaving it to timing.

9 · Mismatched groups, or versions

Group 10 on D1, group 1 on D2, or version 2 on one and version 1 on the other: they never hear each other, so both go active, with standby unknown. Compare show standby vlan 10 on each.

10 · Hosts pointed at a real address

A host whose gateway is D1's own .2, not the virtual .1, loses its gateway when D1 fails, however well HSRP works. Check ipconfig and the DHCP pool's default-router.

The Ticket

Turn it into steps before you open the answer.

Ticket #141-07 · Priority: normal · From: Compliance

We need a record of which device had which IPv6 address on the Shipping LAN. Someone already "turned on DHCPv6" on R2 last week, but when we asked for the list, the record was empty. Please fix it.

One way to break it down
  1. "Turned on DHCPv6" but the record's empty: that's stateless DHCPv6 working as designed. A stateless server keeps no bindings. Nothing is broken; the request needs a different method.
  2. A record of addresses means the server must lease them: stateful DHCPv6.
  3. On R2: a pool with an address prefix (a /80 inside 2001:db8:acad:20::/64 keeps leases away from R2 and SRV1), the DNS server and domain, bound to G0/0/1 in place of the stateless pool.
  4. On G0/0/1: ipv6 nd managed-config-flag (M=1) and ipv6 nd prefix default no-autoconfig (A=0), or every PC keeps an unrecorded SLAAC address too.
  5. Restart each PC's network connection, or the old SLAAC addresses linger (unrecorded) until they age out.
  6. Verify: show ipv6 dhcp binding lists each PC; ipconfig /all shows one global address starting …:20:aaaa:; the gateway is still FE80::2.
  7. Tell Compliance what the record holds: each client's DUID and link-local address, and the leased address, not its MAC. It's a list of current leases, not a history: a lasting record needs the router's DHCPv6 events logged, which is beyond this course.

Worked examples

Think it through before you expand the answer.

Reading the RA

What does this line mean?

show ipv6 interface g0/0/1 on a router ends with Hosts use stateless autoconfig for addresses. and nothing about DHCP. Which method are its hosts using, and what are the flags?

Show answer

SLAAC only: A=1, O=0, M=0, the default once ipv6 unicast-routing is on. With the O flag set, a second line would say hosts use DHCP for other configuration; with M set, the line would say DHCP is used for addresses.

Gateway

Where did fe80::2 come from?

R2 is a stateful DHCPv6 server, and PC-B's ipconfig /all shows an IPv6 address from it. The R2 pool has no gateway line in it at all, but PC-B's default gateway is fe80::2. Where did PC-B get it?

Show answer

From R2's RA. Every RA is sent from the router's link-local address, and hosts use that address as their IPv6 gateway. DHCPv6 has no default-router option, so a DHCPv6 pool can't set one: that's the difference from DHCPv4.

Flags

Why two addresses?

Someone sets up stateful DHCPv6 on a router with ipv6 nd managed-config-flag and a pool with an address prefix. The hosts now each have two global addresses in the same /64. Why?

Show answer

The A flag is still 1. The hosts follow both instructions: A=1 says build a SLAAC address, and M=1 says lease one from DHCPv6. ipv6 nd prefix default no-autoconfig sets A to 0, so hosts stop building one. An existing SLAAC address isn't withdrawn: it ages out, or disappears when the host reconnects.

Stateless

Where are the bindings?

R2 is running stateless DHCPv6, and PC-B has received its DNS server from it. show ipv6 dhcp binding on R2 is empty. Is something broken?

Show answer

No. A stateless server only hands out settings. It leases no addresses, so it has nothing to record. Check ipconfig /all on PC-B instead: the IPv6 DNS server is there.

Election

Who's active?

D1 (.2) and D2 (.3) both run HSRP on VLAN 10 with the default priority and no preemption. They boot at the same moment. Who's active? Then D1 is given priority 150, without preempt. Does anything change?

Show answer

With equal priority, the highest IPv4 address wins: D2 (.3). Giving D1 priority 150 changes nothing while D2 is up: without preemption, the active router stays active. D1 takes over only if D2 fails, or once standby preempt is added on D1.

Timers

How long is Front Desk cut off?

D1 is active for VLAN 10, with the default timers, and loses power. Roughly how long before D2 forwards for 192.168.10.1? Does PC-C need a new gateway address or a new ARP entry?

Show answer

Up to the 10-second hold time: D2 takes over when it has heard no hello from D1 for 10 seconds (hellos come every 3). PC-C changes nothing. D2 takes over the virtual IP and the virtual MAC, so PC-C's gateway and its ARP entry are still right.
