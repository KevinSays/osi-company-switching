Module 4.1

Why VLANs need a router, and three ways to give them one

A VLAN is a broadcast domain, and a subnet. Traffic between two subnets has to be routed, so traffic between two VLANs has to be routed too. That's inter-VLAN routing.

CCNA 1 callback In CCNA 1 you learned that a host sends anything for another network to its default gateway, and that a router interface is the edge of a broadcast domain. Both rules still hold. Each VLAN needs its own gateway address in its own subnet, and each host's gateway must be the one for its own VLAN. A PC in VLAN 30 with gateway 192.168.10.1 is knocking on the wrong door: that address isn't in its subnet, so it can't even reach it.

Module 4.1

Legacy inter-VLAN routing

The oldest method: give the router one physical interface for each VLAN, and cable each one to an access port in that VLAN. It works, and it's simple to read. It also means two VLANs cost two router ports and two switch ports, and twenty VLANs cost twenty of each. Routers don't have that many Ethernet ports, which is why nobody builds it any more. You'll only see it here, as a snippet. We aren't building it.

R1 · legacy, one port per VLAN (illustrative only)
R1(config)# interface g0/0/1 R1(config-if)# ip address 192.168.10.1 255.255.255.0 R1(config-if)# no shutdown R1(config-if)# interface g0/0/2 R1(config-if)# ip address 192.168.30.1 255.255.255.192 R1(config-if)# no shutdown
S1 · one access port per VLAN (illustrative only)
S1(config)# interface g0/1 S1(config-if)# switchport mode access S1(config-if)# switchport access vlan 10 S1(config-if)# interface g0/2 S1(config-if)# switchport mode access S1(config-if)# switchport access vlan 30

HQ can't be built this way: the ISR4321 has no G0/0/2. It has two Gigabit ports, and one of them faces R2. That's the point. VLAN 30 would need a second router port, VLAN 99 a third. One door per department, and you run out of doors.

Module 4.2

Router-on-a-stick

One physical router interface, one cable, one trunk. The router splits its interface into subinterfaces, one per VLAN. Each subinterface is told which VLAN tag it answers to with encapsulation dot1Q, and each one gets the gateway address for that VLAN. Frames come up the trunk tagged, the router routes them, and sends them back down the same cable with the new VLAN's tag.

The router side: one subinterface per VLAN

R1's physical port, G0/0/1, has no address of its own. Each subinterface gets its VLAN with encapsulation dot1Q, then that VLAN's gateway address. The native VLAN's subinterface, .900, gets the native keyword and no address, because nothing on VLAN 900 needs a gateway.

R1 · G0/0/1, one subinterface per VLAN
R1(config)# interface g0/0/1.10 R1(config-subif)# description VLAN 10 FRONT-DESK gateway ! ! Encapsulation first. IOS won't accept an IP address on a LAN subinterface without it. R1(config-subif)# encapsulation dot1Q 10 R1(config-subif)# ip address 192.168.10.1 255.255.255.0 R1(config-subif)# ipv6 address fe80::1 link-local R1(config-subif)# ipv6 address 2001:db8:acad:10::1/64 R1(config-subif)# exit ! R1(config)# interface g0/0/1.30 R1(config-subif)# description VLAN 30 LOGISTICS gateway R1(config-subif)# encapsulation dot1Q 30 ! ! VLAN 30 is the /26 from CCNA 1's VLSM plan, not a /24. R1(config-subif)# ip address 192.168.30.1 255.255.255.192 R1(config-subif)# ipv6 address fe80::1 link-local R1(config-subif)# ipv6 address 2001:db8:acad:30::1/64 R1(config-subif)# exit ! R1(config)# interface g0/0/1.99 R1(config-subif)# description VLAN 99 MGMT gateway R1(config-subif)# encapsulation dot1Q 99 R1(config-subif)# ip address 192.168.99.1 255.255.255.0 R1(config-subif)# ipv6 address fe80::1 link-local R1(config-subif)# ipv6 address 2001:db8:acad:99::1/64 R1(config-subif)# exit ! ! The native VLAN: untagged frames from the trunk land here. It gets no address. R1(config)# interface g0/0/1.900 R1(config-subif)# description Native VLAN 900 (no hosts) R1(config-subif)# encapsulation dot1Q 900 native R1(config-subif)# end R1# copy running-config startup-config
  • The prompt changes to R1(config-subif)#. config-if means the .10 was left off the interface name.
  • The same fe80::1 on every subinterface is fine. A link-local address only has to be unique on its own link, and each subinterface is a separate link. R1 already uses fe80::1 on G0/0/0 and on its loopback.
  • native matches S1's trunk. S1 sends VLAN 900 untagged, so R1 has to file untagged frames under VLAN 900. Without the keyword, R1 would expect VLAN 900 tagged.
  • IPv6 router advertisements now go out on .10, .30 and .99. R1 has had ipv6 unicast-routing since Session 1, so PC-C and PC-D (set to Automatic) give themselves addresses in :10::/64 and :30::/64. That's SLAAC, coming properly in Session 7.

The switch side: a trunk to the router

S1 · G0/1, the trunk to R1
S1# configure terminal S1(config)# interface g0/1 S1(config-if)# description Trunk to R1 G0/0/1 S1(config-if)# switchport mode trunk S1(config-if)# switchport trunk native vlan 900 S1(config-if)# switchport trunk allowed vlan 10,30,99,900 ! ! A router never speaks DTP, so turn it off. S1(config-if)# switchport nonegotiate ! ! Optional tidy-up: the old access VLAN line stays in the config but does nothing on a trunk. S1(config-if)# no switchport access vlan S1(config-if)# end S1# copy running-config startup-config
  • The same settings as the S1–S2 trunk from Session 2, for the same reasons: native 900, an explicit allowed list, and nonegotiate.
  • nonegotiate is safe here. Session 2's rule was "only where the other end is set to trunk by hand." A router is exactly that: it tags frames and never sends DTP.
  • No host changes anything. PC-D's gateway has been 192.168.30.1 since Session 2. With the trunk up, that address finally exists.
Three rules for subinterfaces 1. encapsulation dot1Q comes before the IP address. IOS won't take an address on a subinterface until it knows the VLAN. 2. The subinterface number (.30) is just a label; the encapsulation dot1Q 30 line is what actually matches the tag. Making them match is a habit worth keeping, because a mismatch is an easy fault to miss (Door 1 in the Fault hunt). 3. The no shutdown that matters is on the physical interface. Subinterfaces follow it: shut G0/0/1, and every subinterface goes down with it.

Prove it: cross a VLAN

PC-A · VLAN 10 to VLAN 30
C:\> ping 192.168.30.9 Pinging 192.168.30.9 with 32 bytes of data: Reply from 192.168.30.9: bytes=32 time<1ms TTL=127 Reply from 192.168.30.9: bytes=32 time<1ms TTL=127 Reply from 192.168.30.9: bytes=32 time<1ms TTL=127 Reply from 192.168.30.9: bytes=32 time<1ms TTL=127

TTL=127, not 128. PC-D's reply started at 128 and crossed one router, which took one off. A same-VLAN reply (PC-A to PC-C) comes back at 128. The first ping may time out while R1 ARPs for PC-D.

PC-A · trace the route
C:\> tracert 192.168.30.9 Tracing route to 192.168.30.9 over a maximum of 30 hops: 1 0 ms 0 ms 0 ms 192.168.10.1 2 0 ms 0 ms 0 ms 192.168.30.9 Trace complete.

Hop 1 is PC-A's own gateway, the .10 subinterface. The packet goes up the trunk tagged 10, R1 routes it, and it comes back down the same cable tagged 30. Every inter-VLAN packet crosses that one cable twice. That's router-on-a-stick's limit in one picture.

Module 4.3

Inter-VLAN routing on a Layer 3 switch

A Layer 3 switch can switch frames and route packets, in hardware. Give it one SVI (switch virtual interface, interface vlan N) per VLAN with that VLAN's gateway address, turn on ip routing, and it routes between its own VLANs without ever sending a packet to a router. To reach anything outside HQ, it still needs a link to R1. That link is a routed port: a switch port that stops being a switch port (no switchport) and behaves like a router interface with its own IP address.

CCNA 1 callback You've built SVIs before: every switch management address since CCNA 1 lives on one (interface vlan 1, now interface vlan 99). On a 2960, an SVI is only a way to manage the switch. On D1, an SVI is a real gateway, because D1 can route.

D1's configuration

D1 needs five things: routing turned on, its own copy of the VLANs, a routed port to R1, a trunk to S1, and one SVI per VLAN.

D1 · routing on
D1# configure terminal ! ! A Layer 3 switch doesn't route IPv4 between its interfaces without this. D1(config)# ip routing ! ! And the IPv6 twin, as on R1 in Session 1. D1(config)# ipv6 unicast-routing
D1 · VLANs (the same as S1 and S2)
D1(config)# vlan 10 D1(config-vlan)# name FRONT-DESK D1(config-vlan)# vlan 30 D1(config-vlan)# name LOGISTICS D1(config-vlan)# vlan 99 D1(config-vlan)# name MGMT D1(config-vlan)# vlan 900 D1(config-vlan)# name NATIVE D1(config-vlan)# vlan 999 D1(config-vlan)# name PARKING D1(config-vlan)# exit

There's no VTP in this course, so D1 needs its own copy of every VLAN it uses. Remember: interface vlan 30 does not create VLAN 30.

D1 · G1/0/24, a routed port to R1
D1(config)# interface g1/0/24 D1(config-if)# description Routed link to R1 G0/0/1 ! ! Turns the Layer 2 switchport into a Layer 3 port, like a router interface. D1(config-if)# no switchport D1(config-if)# ip address 10.0.0.10 255.255.255.252 D1(config-if)# ipv6 address fe80::d1 link-local D1(config-if)# ipv6 address 2001:db8:acad:ff03::2/64 D1(config-if)# no shutdown D1(config-if)# end D1# ping 10.0.0.9
  • no switchport comes before the address. A switch port won't take an IP address.
  • fe80::d1 is D1's link-local address on this link. R1's end is fe80::1, and the two ends of a link must differ. d1 is valid hex.
  • A routed port isn't in any VLAN, so it disappears from show vlan brief.
D1 · G1/0/1, the trunk to S1, and the parked ports
D1# configure terminal D1(config)# interface g1/0/1 D1(config-if)# description Trunk to S1 G0/1 ! ! PT's 3650 wants the encapsulation set before trunk mode. A 2960 has no such command. D1(config-if)# switchport trunk encapsulation dot1q D1(config-if)# switchport mode trunk D1(config-if)# switchport trunk native vlan 900 D1(config-if)# switchport trunk allowed vlan 10,30,99,900 D1(config-if)# switchport nonegotiate D1(config-if)# exit ! ! Everything not cabled yet. G1/0/2-4 and G1/0/20-21 get their jobs in Sessions 4, 5 and 10. D1(config)# interface range g1/0/2 - 23 , g1/1/1 - 4 D1(config-if-range)# switchport mode access D1(config-if-range)# switchport access vlan 999 D1(config-if-range)# shutdown D1(config-if-range)# end
The encapsulation line Session 2 promised this would come up. A switch that supports more than one trunk encapsulation needs switchport trunk encapsulation dot1q before switchport mode trunk. Packet Tracer's 3650 behaves that way: it rejects switchport mode trunk until the encapsulation is set. A 2960 has no such command, because it only does 802.1Q. On a real 3650, which also only does 802.1Q, the command may not exist at all. S1 needs no change: its trunk to R1 becomes its trunk to D1, with the same settings. Only the cable moves.
D1 · one SVI per VLAN
D1# configure terminal D1(config)# interface vlan 10 D1(config-if)# description VLAN 10 FRONT-DESK gateway D1(config-if)# ip address 192.168.10.1 255.255.255.0 D1(config-if)# ipv6 address fe80::1 link-local D1(config-if)# ipv6 address 2001:db8:acad:10::1/64 D1(config-if)# no shutdown D1(config-if)# exit ! D1(config)# interface vlan 30 D1(config-if)# description VLAN 30 LOGISTICS gateway D1(config-if)# ip address 192.168.30.1 255.255.255.192 D1(config-if)# ipv6 address fe80::1 link-local D1(config-if)# ipv6 address 2001:db8:acad:30::1/64 D1(config-if)# no shutdown D1(config-if)# exit ! D1(config)# interface vlan 99 D1(config-if)# description VLAN 99 MGMT gateway D1(config-if)# ip address 192.168.99.1 255.255.255.0 D1(config-if)# ipv6 address fe80::1 link-local D1(config-if)# ipv6 address 2001:db8:acad:99::1/64 D1(config-if)# no shutdown D1(config-if)# end
  • The same addresses R1's subinterfaces had: .1 and fe80::1 in every VLAN. Hosts change nothing.
  • SVIs need no shutdown. Unlike R1's subinterfaces, an SVI starts administratively down.
  • D1 has no access ports in VLANs 10, 30 or 99. Each SVI stays up only because the G1/0/1 trunk carries its VLAN. If the trunk drops, or a VLAN leaves its allowed list, that SVI goes up/down.

D1 and R1 also need routes to each other's networks: R1 to the HQ subnets behind D1, and D1 to everything outside HQ. Those are static routes, which are Module 15. The lab provides them.

Module 4.3

Verify the Layer 3 switch

The proof that D1 has taken over is a traceroute: the first hop is the same address as with router-on-a-stick, but now it's D1 answering.

D1: are the SVIs up?

D1 · interfaces (trimmed)
D1# show ip interface brief Interface IP-Address OK? Method Status Protocol GigabitEthernet1/0/1 unassigned YES unset up up GigabitEthernet1/0/2 unassigned YES unset administratively down down ... GigabitEthernet1/0/24 10.0.0.10 YES manual up up ... Vlan10 192.168.10.1 YES manual up up Vlan30 192.168.30.1 YES manual up up Vlan99 192.168.99.1 YES manual up up

All three SVIs up/up is the success check. up down means the VLAN doesn't exist on D1, or no active port carries it. administratively down means a forgotten no shutdown. The full output lists every one of D1's 28 ports; it's trimmed here.

D1: the routing table

D1 · routes
D1# show ip route ... Gateway of last resort is 10.0.0.9 to network 0.0.0.0 10.0.0.0/30 is subnetted, 1 subnets C 10.0.0.8 is directly connected, GigabitEthernet1/0/24 C 192.168.10.0/24 is directly connected, Vlan10 192.168.30.0/26 is subnetted, 1 subnets C 192.168.30.0 is directly connected, Vlan30 C 192.168.99.0/24 is directly connected, Vlan99 S* 0.0.0.0/0 [1/0] via 10.0.0.9
  • One C route per SVI, plus one for the routed port. To the routing table, an SVI is a routed interface.
  • S* is the provided default route. The * marks it as the candidate default, which is why the gateway of last resort is set.
  • Packet Tracer's 3650 may also print L (local) lines and "variably subnetted" headings, like R1 does.

The gateway moved. The trace didn't.

PC-A · trace to PC-D, through D1
C:\> tracert 192.168.30.9 Tracing route to 192.168.30.9 over a maximum of 30 hops: 1 0 ms 0 ms 0 ms 192.168.10.1 2 0 ms 0 ms 0 ms 192.168.30.9 Trace complete.

Identical to the router-on-a-stick trace. Hop 1 is still 192.168.10.1, but now it's D1's Vlan10 SVI answering, not R1. The packet never leaves the HQ switches: S1 to D1, routed inside D1, then back down to S1, across to S2, and out to PC-D. What changed? The box, not the address.

PC-A · trace to SRV1, through D1
C:\> tracert 192.168.20.100 Tracing route to 192.168.20.100 over a maximum of 30 hops: 1 0 ms 0 ms 0 ms 192.168.10.1 2 0 ms 0 ms 0 ms 10.0.0.9 3 0 ms 0 ms 0 ms 10.0.0.2 4 0 ms 0 ms 0 ms 192.168.20.100 Trace complete.

One more hop than with router-on-a-stick: D1, then R1 (answering from 10.0.0.9, its end of the new link), then R2, then SRV1. Each router answers from the interface the trace arrived on.

Module 4.4

Troubleshoot inter-VLAN routing

Work from the host outward: the host's own settings, its access port, the trunk, then the router or Layer 3 switch. Every fault below breaks something specific, and one command shows it.

Read the pattern Which VLANs are broken tells you where to look. One VLAN broken: that VLAN's subinterface or SVI, its allowed-list entry, or one host. Every VLAN broken: the shared piece, which is the trunk to the router, the router's physical port, or ip routing. One host broken while its neighbors work: that host's settings or its access port.

The Wrong Door

Fault hunt

Each config below has one bug. Find it before you open the answer. Each one is a fault from the Troubleshoot table.

Door 1

Symptom: With router-on-a-stick, PC-D (VLAN 30) can't ping 192.168.30.1. VLANs 10 and 99 work. R1's show ip interface brief shows every subinterface up/up.

R1 · show running-config (part)
R1# show running-config ... interface GigabitEthernet0/0/1.10 encapsulation dot1Q 10 ip address 192.168.10.1 255.255.255.0 interface GigabitEthernet0/0/1.30 encapsulation dot1Q 3 ip address 192.168.30.1 255.255.255.192 interface GigabitEthernet0/0/1.99 encapsulation dot1Q 99 ip address 192.168.99.1 255.255.255.0

B. The subinterface name is only a label. The encapsulation dot1Q number decides which frames it hears, and nothing arrives tagged 3. The /26 is correct (A), up/up rules out C, and the number doesn't have to match anything (D). show interfaces g0/0/1.30 shows Vlan ID 3.

Door 2

Symptom: With router-on-a-stick, nobody at HQ can reach their gateway, not even VLAN 10, which worked all through Session 2.

S1 · show running-config interface g0/1
S1# show running-config interface g0/1 interface GigabitEthernet0/1 description Trunk to R1 G0/0/1 switchport access vlan 10 switchport mode access

B. R1's subinterfaces expect tagged frames. An access port sends them untagged, so everything lands on .900, which has no address. The description says "Trunk", but descriptions don't configure anything. show interfaces trunk shows no Gig0/1. C would actually break .10 (fault 10).

Door 3

Symptom: After D1 takes over, PC-A reaches 192.168.10.1 and PC-C. PC-D reaches 192.168.30.1. But PC-A can't ping PC-D, and nobody reaches SRV1.

D1 · what routing is on?
D1# show running-config | include routing ipv6 unicast-routing

C. Only the IPv6 routing command is there. Without ip routing, D1 answers on each SVI but forwards nothing between them. Both gateways answer, which rules out A and D. PC-A to PC-D never uses a default route, because both subnets are directly connected to D1, which rules out B.

Door 4

Symptom: After D1 takes over, PC-A and PC-D can ping each other, but nobody at HQ reaches SRV1. D1 can't ping 10.0.0.9.

D1 · show running-config interface g1/0/24
D1# show running-config interface g1/0/24 interface GigabitEthernet1/0/24 description Routed link to R1 G0/0/1

B. The port is still a switch port, so the ip address command was rejected, and nobody noticed. show ip interface brief shows G1/0/24 unassigned. A and D only matter once the link works. Inter-VLAN traffic works, which rules out C. Fix: no switchport, then the addresses.

Hands-On · Packet Tracer

Lab: open the doors, then hand them over

Two Packet Tracer files, and no recabling in either. Part A builds router-on-a-stick on HQ. Part B moves the job to D1 without changing a single host setting. The configuration is in the sections above. This is the order to do it in, and why the order matters.

Part A · Router-on-a-stick

The file opens where Session 2 ended. S1 G0/1, the port facing R1, is still a VLAN 10 access port, and R1 G0/0/1 still holds 192.168.10.1. PC-C and PC-D have IPv6 set to Automatic.

  1. Router first. Clear the old addresses off R1's physical port, because the .10 subinterface is about to need 192.168.10.1, and IOS won't let two interfaces share one subnet.
R1 · clear the physical interface
R1# configure terminal R1(config)# interface g0/0/1 R1(config-if)# description Trunk to S1 G0/1 R1(config-if)# no ip address ! ! With no argument, this removes every IPv6 address on the port, link-local included. R1(config-if)# no ipv6 address ! ! The physical port stays up. Its subinterfaces need it. R1(config-if)# no shutdown R1(config-if)# exit
  1. The subinterfaces, as in Router-on-a-stick.
Why did PC-A just lose its gateway? Ping 192.168.10.1 from PC-A at this point and it fails, even though VLAN 10 worked all through Session 2. R1 now expects frames tagged, and S1 G0/1 is still an access port sending them untagged. Untagged frames land on .900, which has no address. The next step fixes it.
  1. The trunk on S1 G0/1, as in Router-on-a-stick.
  2. Verify with Verify router-on-a-stick, including every row of its "Also test" table.

Part B · Hand the doors to D1

The file opens from the finished Part A network, with D1 already added and cabled: R1 G0/0/1 now goes to D1 G1/0/24, and S1 G0/1 goes to D1 G1/0/1. D1's basic settings (hostname, passwords, SSH) are already done. R1's subinterfaces are still configured.

Order matters here. R1 G0/0/1 now faces D1's routed port, not a trunk, so its old subinterfaces are dead ends. But while they exist, R1 still lists the HQ subnets as directly connected, and it would ignore the routes pointing at D1. So R1 gives up the doors first, and D1 takes them second.

  1. R1 gives up the doors.
R1 · remove the subinterfaces, readdress G0/0/1
R1# configure terminal R1(config)# no interface g0/0/1.10 R1(config)# no interface g0/0/1.30 R1(config)# no interface g0/0/1.99 R1(config)# no interface g0/0/1.900 ! R1(config)# interface g0/0/1 R1(config-if)# description Routed link to D1 G1/0/24 R1(config-if)# ip address 10.0.0.9 255.255.255.252 R1(config-if)# ipv6 address fe80::1 link-local R1(config-if)# ipv6 address 2001:db8:acad:ff03::1/64 R1(config-if)# no shutdown R1(config-if)# end

G0/0/1 is back to being a plain routed port, like G0/0/0, on a new /30 that links R1 and D1. (On real routers, a deleted subinterface may linger in show ip interface brief as deleted until the next reload. Its configuration is gone.)

  1. D1, in this order: routing, the VLANs, the routed port to R1, the trunk to S1, and the SVIs last, as in Inter-VLAN routing on a Layer 3 switch. Get the ping from D1 to 10.0.0.9 working before the trunk.
  2. The provided routes.
Beyond Module 4: static routes Static routes are Module 15 (Session 11). Here they're provided so HQ can reach the rest of the network.

Type these exactly. In Part A the HQ networks were directly connected to R1. Now they're connected to D1, one hop away, so R1 needs to be told where they are, and D1 needs to be told where everything else is.

R1 · the HQ networks are behind D1
R1# configure terminal R1(config)# ip route 192.168.10.0 255.255.255.0 10.0.0.10 ! ! The /26 mask, not /24. R1(config)# ip route 192.168.30.0 255.255.255.192 10.0.0.10 R1(config)# ip route 192.168.99.0 255.255.255.0 10.0.0.10 R1(config)# ipv6 route 2001:db8:acad:10::/64 2001:db8:acad:ff03::2 R1(config)# ipv6 route 2001:db8:acad:30::/64 2001:db8:acad:ff03::2 R1(config)# ipv6 route 2001:db8:acad:99::/64 2001:db8:acad:ff03::2 R1(config)# end R1# copy running-config startup-config
D1 · everything else is through R1
D1# configure terminal D1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.9 D1(config)# ipv6 route ::/0 2001:db8:acad:ff03::1 D1(config)# end D1# copy running-config startup-config

R2 needs nothing. Its default route already sends every HQ-bound packet to R1, and R1 now knows the way to D1.

  1. Clear the stale caches.

The PCs and switches may still have R1's MAC address cached for 192.168.10.1, .30.1 and .99.1. The address is the same, but the box behind it isn't. If a ping to the gateway fails right after the swap, clear the cache: arp -d on PC-A, PC-C and PC-D, and clear arp-cache on S1 and S2. Real devices usually fix this on their own, because a new SVI announces itself with a gratuitous ARP. Packet Tracer may not.

  1. Verify with Verify the Layer 3 switch, and test every row of What works now.

Recurring segment

The Ticket

Turn it into steps before you open Packet Tracer.

Ticket #141-03 · Priority: medium · From: Logistics

Since the new switch went in, PC-D can print to the shared printer in our own office, but it can't get to anything at Front Desk or the website. Nobody touched PC-D. Somebody said "the gateway" but we don't know what that means.

One way to break it down
  1. "Can reach our own office": same-VLAN traffic works, so PC-D's access port, its VLAN, and its address and mask are probably fine. The problem is anything that needs a gateway.
  2. Check PC-D's settings first: ipconfig. The gateway must be 192.168.30.1, and the mask must be /26 (255.255.255.192). A gateway of 192.168.10.1 is the wrong door, and it's outside PC-D's subnet, so PC-D can't reach it at all.
  3. If the PC is right, check the door itself on D1: show ip interface brief | include Vlan30. It should be up up with 192.168.30.1. If it's down, check that VLAN 30 exists on D1 (show vlan brief) and that it crosses the D1–S1 trunk and the S1–S2 trunk (show interfaces trunk, "allowed and active").
  4. "Nobody touched PC-D" while "the new switch went in" points at D1, not the PC. Did ip routing make it into D1's config? Without it, D1 won't route between the VLANs at all.
  5. Verify: from PC-D, ping 192.168.30.1, then ping 192.168.10.10 (PC-A), then tracert 192.168.20.100 (SRV1). The first hop should be 192.168.30.1.

Applied

Worked examples

Think it through before you expand the answer.

Gateways

Same subnet, wrong door

PC-D (192.168.30.9/26) has its gateway set to 192.168.30.62. It can ping PC-D's neighbors in VLAN 30, but nothing else. Its address and mask are right. What's wrong, and why doesn't the PC complain?

Show answer

192.168.30.62 is inside PC-D's subnet (usable .1–.62), so nothing about the setting looks wrong. But nothing owns that address: the gateway is 192.168.30.1. PC-D ARPs for .62, nobody answers, and every packet for another network goes nowhere. A host doesn't check that its gateway is the right address, or that anything owns it. Fix: set the gateway to 192.168.30.1.

Subinterfaces

The number that doesn't matter

A classmate configures interface g0/0/1.30 with encapsulation dot1Q 10 and ip address 192.168.30.1 255.255.255.192. Their g0/0/1.10 is correct. What breaks?

Show answer

On a real router, IOS refuses encapsulation dot1Q 10 on .30, because VLAN 10 already belongs to .10. Then the ip address line is refused too, because .30 has no encapsulation. Packet Tracer may accept both; check. Either way, nothing answers for VLAN 30's tag, so PC-D can't reach 192.168.30.1. The .30 in the name is only a label. The encapsulation dot1Q line is what matters. show interfaces g0/0/1.30, or show running-config, shows which subinterface has which VLAN.

Layer 3 switch

Everything's up, nothing routes

On D1, show ip interface brief shows Vlan10, Vlan30 and Vlan99 all up/up with the right addresses. PC-A can ping 192.168.10.1, and PC-D can ping 192.168.30.1. But PC-A can't ping PC-D. What did someone forget?

Show answer

ip routing. Without it, a Layer 3 switch answers on each SVI like a host would, but it won't forward packets between them. show ip route is the giveaway: without ip routing there are no C routes for the SVIs. Real IOS prints a short "Default gateway is not set" table instead. Turn it on in global config.

Routed ports

The port that wouldn't take an address

On D1, interface g1/0/24, then ip address 10.0.0.10 255.255.255.252, gives an error. Why?

Show answer

It's still a switch port, and switch ports don't have IP addresses: they belong to a VLAN. Run no switchport first to make it a routed port, then add the address.

The swap

Why didn't the PCs notice?

When D1 took over from R1, nobody changed a single setting on PC-A, PC-C or PC-D. Explain why they still work, and why a ping right after the swap might fail once.

Show answer

The hosts only know their gateway's IP address, and D1's SVIs use the same addresses R1's subinterfaces used. What changed is the MAC address behind that IP. A host that cached R1's MAC for 192.168.10.1 keeps sending to it until the ARP entry times out or is cleared. That's why the first pings can fail, and why arp -d on the PC fixes it straight away.
