Module 3.1

The Sprawl: one broadcast domain

Before any VLAN work, every port on S1 and S2 is in VLAN 1. Prove it's a problem first.

CCNA 1 callback CCNA 1's final review promised this: "why the lab switches only use VLAN 1." And in The Zoning Office, The Sprawl was the villain: one giant broadcast domain. In CCNA 1 the only way to split a broadcast domain was a router. Session 1 reminded you why: switches flood broadcasts out every port.

In today's starting file, S1 F0/23 and S2 F0/23 are both at their factory default, which makes them an ordinary access link in VLAN 1. So the two switches form one big broadcast domain. Make PC-A send a broadcast, then look at S2:

PC-A · force an ARP broadcast
C:\> arp -d C:\> ping 192.168.10.1
S2 · who has S2 heard from?
S2# show mac address-table Mac Address Table ------------------------------------------- Vlan Mac Address Type Ports ---- ----------- -------- ----- 1 0060.5c3b.a801 DYNAMIC Fa0/23
  • PC-A's MAC shows up on S2, learned on Fa0/23. The only way S2 could learn it is if a frame from PC-A crossed into S2: PC-A's ARP broadcast, flooded by S1 and then flooded again by S2.
  • R1's MAC doesn't show up on S2. R1's reply was a unicast to PC-A, and S1 already knew PC-A was on Fa0/1, so the reply never left S1.
  • Run clear mac address-table dynamic on S2 first for a clean result. Your MAC addresses will differ.
See it: Simulation mode In Packet Tracer, switch to Simulation, filter for ARP, and repeat the ping. Watch PC-A's broadcast reach PC-C and PC-D. PC-D is in a different subnet (192.168.30.0/26), but it's in the same broadcast domain, so it still has to receive the frame and throw it away. Multiply that by every host and every broadcast: that's The Sprawl. (This is the idea behind NetAcad's activity 3.1.4, "Who Hears the Broadcast?")

Module 3.1

What a VLAN is

A VLAN (virtual LAN) is a group of switch ports that behaves as its own separate LAN. Each VLAN is its own broadcast domain and, by convention, its own IP subnet. Hosts in different VLANs can't talk to each other unless something routes between them, exactly as if they were plugged into different switches.

Why bother

  • Smaller broadcast domains: fewer devices hear each broadcast
  • Better security: only users in the same VLAN can reach each other directly
  • IT efficiency: group users by role, not by where their desk is
  • Lower cost: fewer switches and uplinks for the same separation
  • Better performance: less unnecessary traffic on every link
  • Simpler management: one VLAN per department or application

Types of VLANs

Module 3.2

VLANs across switches: tags and trunks

PC-A is in VLAN 10 on S1. PC-C is in VLAN 10 on S2. The frames between them cross one cable that also carries VLANs 30 and 99. How does S2 know which VLAN a frame belongs to?

The link between the switches is a trunk: a point-to-point link that carries more than one VLAN. On a trunk, the sending switch adds an IEEE 802.1Q tag to each frame that says which VLAN it belongs to. The receiving switch reads the tag and forwards the frame only to ports in that VLAN, removing the tag when the frame leaves an access port. Hosts never see tags; access ports send and receive ordinary, untagged frames.

802.1Q tag fieldSizeWhat it holds
Type (TPID)2 bytes0x8100: "this frame is tagged"
User priority3 bitsClass of service (CoS), used for voice priority
CFI1 bitCanonical format identifier (legacy)
VLAN ID (VID)12 bitsThe VLAN number, which is why VLAN IDs top out near 4,096

The whole tag is 4 bytes, inserted after the source MAC address. Because the frame changed, the switch recalculates the FCS.

CCNA 1 callback The Ethernet II frame from CCNA 1 Session 5: preamble, destination MAC, source MAC, type, data, FCS. The 802.1Q tag slides in right after the source MAC, so a tagged frame is 4 bytes longer.

The native VLAN

One VLAN on each trunk crosses untagged: the native VLAN. Any untagged frame that arrives on a trunk is put in the native VLAN. It exists for compatibility with devices that don't tag. Both ends of a trunk must use the same native VLAN, and best practice is a native VLAN with no hosts in it, which is why ours is VLAN 900.

The voice VLAN

An IP phone is really a tiny three-port switch: one port to the wall, one to the PC, one internal. The switch port it plugs into carries two VLANs at once: the PC's data VLAN (untagged) and the voice VLAN (tagged, with a CoS priority). The switch tells the phone which voice VLAN to use with CDP.

Module 3.3

Create VLANs and assign ports

Two steps: create the VLAN (and name it), then put access ports in it. Both happen on every switch that uses the VLAN. This course doesn't use VTP, so nothing copies VLANs between switches for you.

S1 · what a new switch looks like
S1# show vlan brief VLAN Name Status Ports ---- -------------------------------- --------- ------------------------------- 1 default active Fa0/1, Fa0/2, Fa0/3, Fa0/4 Fa0/5, Fa0/6, Fa0/7, Fa0/8 Fa0/9, Fa0/10, Fa0/11, Fa0/12 Fa0/13, Fa0/14, Fa0/15, Fa0/16 Fa0/17, Fa0/18, Fa0/19, Fa0/20 Fa0/21, Fa0/22, Fa0/23, Fa0/24 Gig0/1, Gig0/2 1002 fddi-default active 1003 token-ring-default active 1004 fddinet-default active 1005 trnet-default active

Every port is in VLAN 1, plus the four reserved VLANs. (A real 2960 writes Gi0/1 and shows the reserved VLANs as act/unsup; Packet Tracer writes it as shown.)

Step 1: create and name the VLANs

S1 · create VLANs (then the same on S2)
S1# configure terminal S1(config)# vlan 10 S1(config-vlan)# name FRONT-DESK S1(config-vlan)# vlan 30 S1(config-vlan)# name LOGISTICS S1(config-vlan)# vlan 99 S1(config-vlan)# name MGMT S1(config-vlan)# vlan 900 S1(config-vlan)# name NATIVE S1(config-vlan)# vlan 999 S1(config-vlan)# name PARKING S1(config-vlan)# end
  • You can go from one vlan straight to the next without leaving VLAN configuration mode.
  • Every switch needs its own copy of each VLAN it uses. Run the same block on S2. S3 at R2's site gets none of these; it has its own VLAN 20.

Step 2: assign access ports

S1 · access ports (then the same on S2)
S1# configure terminal S1(config)# interface range f0/1 - 10 S1(config-if-range)# switchport mode access S1(config-if-range)# switchport access vlan 10 S1(config-if-range)# interface range f0/11 - 20 S1(config-if-range)# switchport mode access S1(config-if-range)# switchport access vlan 30 S1(config-if-range)# exit ! ! The link to R1 stays in VLAN 10, so PC-A keeps its gateway. S1(config)# interface g0/1 S1(config-if)# switchport mode access S1(config-if)# switchport access vlan 10 S1(config-if)# end
  • switchport mode access first. It makes the port permanently an access port, so DTP can't turn it into a trunk.
  • interface range takes a space on each side of the hyphen (f0/1 - 10), and commas join ranges (f0/21 - 22 , f0/24).
  • On S2, run the same block without the g0/1 part: S2's G0/1 is parked later today. PC-C ends up in VLAN 10 on F0/1, and PC-D in VLAN 30 on F0/11.
  • If you assign a port to a VLAN that doesn't exist yet, the switch creates it for you, with a default name such as VLAN0030 instead of yours.

Example: a voice VLAN

Our network has no IP phones, so this is for the syntax only, on a spare port. Remove it afterward.

S1 · voice VLAN (illustration only)
S1(config)# vlan 150 S1(config-vlan)# name VOICE S1(config-vlan)# exit S1(config)# interface f0/9 S1(config-if)# switchport mode access S1(config-if)# switchport access vlan 10 S1(config-if)# mls qos trust cos S1(config-if)# switchport voice vlan 150 S1(config-if)# end ! ! Now undo it. S1# configure terminal S1(config)# interface f0/9 S1(config-if)# no switchport voice vlan S1(config-if)# no mls qos trust cos S1(config-if)# exit S1(config)# no vlan 150 S1(config)# end
Beyond this course mls qos trust cos tells the switch to trust the phone's priority marking. That's QoS, which NetAcad lists as beyond this course: recognize it, don't worry about it.

Move management to VLAN 99

Session 1 left S1's management address on VLAN 1, with a promise. Here it moves.

Session 1 callback Remember the SVI rule from Session 1: an SVI comes up only when a port carrying its VLAN is up. That rule is about to matter.
S1 · retire VLAN 1, build VLAN 99 (S2 uses .12)
S1# configure terminal ! ! Retire the VLAN 1 management address. S1(config)# interface vlan 1 S1(config-if)# no ip address S1(config-if)# shutdown S1(config-if)# exit ! ! The new management SVI. S1(config)# interface vlan 99 S1(config-if)# ip address 192.168.99.11 255.255.255.0 S1(config-if)# no shutdown S1(config-if)# exit ! ! A new ip default-gateway replaces the old one. 192.168.99.1 won't exist until Session 3. S1(config)# ip default-gateway 192.168.99.1 S1(config)# end S1# show ip interface brief | include Vlan Vlan1 unassigned YES manual administratively down down Vlan99 192.168.99.11 YES manual up down

Notice S3 S3 at R2's site manages itself on VLAN 20, and R2 has never heard of "VLAN 20": R2's port is just a router port. VLAN numbers mean something only inside the switches that have them.
You just lost SSH from PC-A, and that's expected PC-A is in VLAN 10. S1's management address is now in VLAN 99. Nothing routes between VLANs yet, so PC-A can't reach S1 or S2 over the network until Session 3. Use the console in the meantime.

Module 3.3

Change, delete, and reset VLANs

The rule NetAcad wants you to remember: move the ports out before you delete a VLAN.

Move a port back to VLAN 1

S1
S1(config)# interface f0/10 S1(config-if)# no switchport access vlan S1(config-if)# end

F0/10 now shows under VLAN 1. Put it back with switchport access vlan 10.

Delete a VLAN that still has ports (try it on S2, then undo)

S2
S2(config)# no vlan 30 S2(config)# end S2# show interfaces f0/11 switchport | include Access Mode Access Mode VLAN: 30 (Inactive)

Ports F0/11–F0/20 vanish from show vlan brief, and PC-D is cut off. The ports don't fall back to VLAN 1. Fix: vlan 30, name LOGISTICS, and they come back.

Reset every VLAN on a switch

Scratch switch only, not the course file
Switch# delete flash:vlan.dat Delete filename [vlan.dat]? Delete flash:/vlan.dat? [confirm] Switch# erase startup-config Erasing the nvram filesystem will remove all configuration files! Continue? [confirm] [OK] Erase of nvram: complete Switch# reload Proceed with reload? [confirm]
Why both? VLANs live in vlan.dat, not the startup config. Erasing only the startup config leaves the VLANs behind after the reload, which surprises everyone the first time. NetAcad's full reset: unplug the data cables, erase the startup config, delete vlan.dat, reload.

Module 3.4

Build the trunk: S1 F0/23 ↔ S2 F0/23

The link between the switches has been an ordinary access link in VLAN 1. Now it becomes a trunk carrying VLANs 10, 30, 99, and 900, with 900 as the native VLAN.

S1 · F0/23 trunk (then exactly the same on S2)
S1# configure terminal S1(config)# interface f0/23 S1(config-if)# switchport mode trunk S1(config-if)# switchport trunk native vlan 900 S1(config-if)# switchport trunk allowed vlan 10,30,99,900 S1(config-if)# switchport nonegotiate S1(config-if)# end
  • No encapsulation command. The 2960 only does 802.1Q. A Layer 3 switch such as the 3560 needs switchport trunk encapsulation dot1q before switchport mode trunk, and NetAcad's Packet Tracer activities type it on the 3650 too. You'll meet one in Session 3.
  • Between configuring S1 and S2, S1 logs a native VLAN mismatch for a moment, because S2 still uses native 1. It stops once both ends match.
  • Configure both ends. If S1 is trunk + nonegotiate while S2 is still dynamic auto, S2 never hears a DTP request and stays an access port: a one-sided trunk. nonegotiate belongs only where the far end is also set to trunk.
S1 · show interfaces trunk
S1# show interfaces trunk Port Mode Encapsulation Status Native vlan Fa0/23 on 802.1q trunking 900 Port Vlans allowed on trunk Fa0/23 10,30,99,900 Port Vlans allowed and active in management domain Fa0/23 10,30,99,900 Port Vlans in spanning tree forwarding state and not pruned Fa0/23 10,30,99,900
  1. Mode, encapsulation, status, native VLAN. on means a static trunk.
  2. Allowed: what you permitted.
  3. Allowed and active: permitted and the VLAN exists on this switch. A VLAN you forgot to create drops out here.
  4. Forwarding: what Spanning Tree is actually forwarding. This gets interesting in Session 4.

Reset a trunk to its defaults

S1
S1(config)# interface f0/23 S1(config-if)# no switchport trunk allowed vlan S1(config-if)# no switchport trunk native vlan S1(config-if)# end

Now every VLAN is allowed and the native VLAN is 1. To make the port an access port again, use switchport mode access. Then put the course configuration back.

Module 3.4

Native VLAN mismatch

The most common trunk mistake, and the one CDP warns you about.

Try it: on S2 only, run no switchport trunk native vlan on F0/23, which sends S2 back to native VLAN 1. Within a minute:

S1 · console message
%CDP-4-NATIVE_VLAN_MISMATCH: Native VLAN mismatch discovered on FastEthernet0/23 (900), with S2 FastEthernet0/23 (1).
  • Tagged VLANs (10, 30, 99) keep working. Their frames carry a tag, so both ends agree.
  • Untagged traffic crosses between VLANs. An untagged frame S1 sends in VLAN 900 arrives in VLAN 1 on S2, and the other way around. Two VLANs that should be separate are leaking into each other. The untagged native VLAN is also what the double-tagging (VLAN hopping) attack in Session 8 abuses.
  • CDP repeats the warning about once a minute, on both switches.
  • Fix: put switchport trunk native vlan 900 back on S2.
Coming up in Session 4 On real switches, Spanning Tree also notices the mismatch and blocks the affected VLANs on that port. Packet Tracer may only show the CDP message.

Module 3.5

DTP: trunks that build themselves

Dynamic Trunking Protocol is Cisco's protocol for two switch ports to negotiate whether their link becomes a trunk. It's on by default. That's convenient when it works, and a security problem when someone plugs in a device that asks for a trunk. Best practice: set every port's mode yourself, and turn DTP off with switchport nonegotiate.

ModeWhat it does
switchport mode accessAlways an access port. Tells the neighbor to be an access link, too.
switchport mode trunkAlways a trunk. Tells the neighbor to become a trunk.
switchport mode dynamic desirableAsks the neighbor to trunk
switchport mode dynamic autoTrunks only if asked. The 2960's default.
switchport nonegotiateSends no DTP at all. Only allowed with access or trunk. On a trunk, the far end must also be set to trunk by hand.

Which pairs form a trunk

Dynamic autoDynamic desirableTrunkAccess
Dynamic autoAccessTrunkTrunkAccess
Dynamic desirableTrunkTrunkTrunkAccess
TrunkTrunkTrunkTrunkLimited connectivity
AccessAccessAccessLimited connectivityAccess

The trap is the top-left cell. Auto plus auto gives an access link: both ends are willing, but neither one asks. That's exactly how S1 and S2 were cabled at the start of today.

Drill · Will it trunk?

See the trap on today's starting link

S1 · before the trunk was built
S1# show interfaces f0/23 switchport Name: Fa0/23 Switchport: Enabled Administrative Mode: dynamic auto Operational Mode: static access Administrative Trunking Encapsulation: dot1q Operational Trunking Encapsulation: native Negotiation of Trunking: On Access Mode VLAN: 1 (default) ...

Configured as dynamic auto, operating as an access port. Once PC-A and PC-C move to VLAN 10, this link carries only VLAN 1, so they can't reach each other. That's why the trunk is set by hand.

Park the unused ports

One last tidy-up. Ports outside the plan go into VLAN 999, a VLAN with no gateway and no hosts, and get shut down. Session 9 explains why in full; today, just build the habit.

S1 · park the ports outside the plan
S1# configure terminal S1(config)# interface range f0/21 - 22 , f0/24 , g0/2 S1(config-if-range)# switchport mode access S1(config-if-range)# switchport access vlan 999 S1(config-if-range)# shutdown S1(config-if-range)# end

On S2 the range is f0/21 - 22 , f0/24 , g0/1 - 2. F0/24 and the Gigabit uplinks are waiting for Sessions 4 and 5.

A parked port is doubly safe: it's shut, and even if someone turns it on, they land in a VLAN with no gateway and no other hosts. In Session 9 you'll also park the unused ports inside the VLAN 10 and 30 ranges.

Watch for this

Common Module 3 mistakes

Two of these come up more than any others: access-port VLAN membership, and trunk and DTP settings.

1 · A host in the wrong VLAN

PC-C's port was left in VLAN 1, or put in VLAN 30. From PC-A, ping 192.168.10.11 times out, even though both PCs are on 192.168.10.0/24, so the IP settings look fine. show vlan brief on S2 shows Fa0/1 under the wrong VLAN. Fix: switchport access vlan 10.

2 · The VLAN doesn't exist on the far switch

The VLAN appears in "allowed on trunk" but is missing from "allowed and active" in show interfaces trunk. Watch for this with VLAN 99: interface vlan 99 creates the SVI, but it does not create VLAN 99 itself.

3 · A VLAN left off the allowed list

S1 · allowed list typed as 10,30,900
S1# show ip interface brief | include Vlan99 Vlan99 192.168.99.11 YES manual up down

VLAN 99 isn't carried, so both management SVIs go up/down and the switches can't ping each other. Fix: switchport trunk allowed vlan add 99 on both ends. Don't retype the list without add: that replaces it.

4 · Native VLAN mismatch

The CDP NATIVE_VLAN_MISMATCH message, repeating. Set the same native VLAN at both ends. (See Native mismatch.)

5 · Auto + auto, so no trunk

show interfaces trunk prints nothing, and show interfaces f0/23 switchport shows Administrative Mode: dynamic auto, Operational Mode: static access. Fix: switchport mode trunk on both ends.

6 · Deleting a VLAN with ports in it

The ports disappear from show vlan brief and show Access Mode VLAN: 30 (Inactive). Recreate the VLAN, or reassign the ports first next time.

7 · nonegotiate on a dynamic port

Command rejected: Conflict between 'nonegotiate' and 'dynamic' status. Set the mode by hand first.

8 · Reading up/down as "forgot no shutdown"

administratively down means you forgot no shutdown. up down on an SVI means no up port carries that VLAN: check the trunk and the allowed list.

Ticket #141-02 · Priority: high · From: Logistics

We hired a new Logistics person and put them at the empty desk upstairs, by S2's port 14. They can't reach PC-D, who sits on the same team. Front Desk says they can see our traffic, which is not OK. Please fix by tomorrow.

One way to break it down
  1. "Can't reach PC-D, same team": both should be in VLAN 30. Check show vlan brief on S2: is F0/14 in VLAN 30, or still in VLAN 1? If it's in VLAN 999 and shut (parked), it needs to be un-parked: switchport access vlan 30, no shutdown.
  2. Check the new PC's address: it must be inside 192.168.30.0/26 (usable .1–.62; pick an unused static address in .2–.8, because .1 is the future gateway, .9 is PC-D, and .10–.62 becomes the DHCP pool in Session 6), with a /26 mask, not /24, and gateway 192.168.30.1.
  3. "Front Desk can see our traffic": a port is in the wrong VLAN. If the new PC landed in VLAN 10, or VLAN 1 still spans both switches, the broadcast domains are mixed. show interfaces f0/14 switchport: Access Mode VLAN should be 30.
  4. Verify: ping PC-D from the new PC. Then confirm in Simulation mode that its ARP broadcasts don't reach PC-A or PC-C.

Trunks

Same VLAN, different switches, no ping

PC-A (S1, VLAN 10) can't ping PC-C (S2, VLAN 10). Both ports show the right VLAN in show vlan brief. On S1, show interfaces trunk prints nothing at all. What's wrong?

Show answer

The link between the switches isn't a trunk. An empty show interfaces trunk means no port is trunking. Most likely both ends are still dynamic auto, which forms an access link in VLAN 1, so VLAN 10 frames can't cross. Fix: switchport mode trunk on F0/23 at both ends, then the native and allowed VLAN settings.

Allowed VLANs

The one-word mistake

The trunk allows 10,30,99,900. You want to add VLAN 40 later, so you type switchport trunk allowed vlan 40. What happens?

Show answer

The allowed list becomes only VLAN 40. VLANs 10, 30, 99 and 900 stop crossing the trunk: PC-A loses PC-C, and the management SVIs drop to up/down. The right command is switchport trunk allowed vlan add 40. (There's also remove, except, and all.)

Deleting VLANs

Where did ten ports go?

After no vlan 30 on S2, ports F0/11–F0/20 don't appear anywhere in show vlan brief, and PC-D can't reach anything. Did they move to VLAN 1?

Show answer

No. They're still assigned to VLAN 30, which no longer exists, so they're inactive. show interfaces f0/11 switchport shows Access Mode VLAN: 30 (Inactive). They don't move to VLAN 1 by themselves. Fix: recreate VLAN 30 (vlan 30, name LOGISTICS) and the ports come back, or reassign them first if you really meant to delete it.

Resetting

The VLANs that came back from the dead

A classmate runs erase startup-config and reload to "wipe" S2. When it boots, the hostname is gone, but show vlan brief still lists VLANs 10, 30, 99, 900 and 999. Why?

Show answer

Normal-range VLANs live in vlan.dat in flash, not in the startup configuration. Erasing the startup config doesn't touch them. A full reset is: delete flash:vlan.dat, erase startup-config, then reload.

Broadcast domains

Count them again

At the end of today, how many broadcast domains does HQ (S1, S2, and R1's LAN interface) have, counting only VLANs that contain hosts or a switch SVI?

Show answer

Three: VLAN 10 (PC-A, PC-C, R1), VLAN 30 (PC-D), and VLAN 99 (the two switch SVIs, carried by the trunk). VLAN 900 has no hosts or SVIs (it only labels untagged frames on the trunk), VLAN 999's ports are shut, and VLAN 1 is empty. Before today, the same HQ was one broadcast domain. That's The Sprawl, beaten, at least at HQ.
