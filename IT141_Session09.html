Module 11.1

Port security

Port security limits how many MAC addresses may use a port, and which ones. Each frame's source MAC is checked against the port's list of secure MAC addresses. That stops MAC address flooding cold: the thousandth made-up address never gets in.

Only on a port that's been told what it is

Illustration A 2960 straight out of the box, not an HQ switch (look at the prompt).
A factory-default 2960 · port security on a dynamic port
Switch# configure terminal Switch(config)# interface f0/1 Switch(config-if)# switchport port-security Command rejected: FastEthernet0/1 is a dynamic port. Switch(config-if)# switchport mode access Switch(config-if)# switchport port-security Switch(config-if)# end

Port security works only on a port set to access (or trunk) by hand. A default 2960 port is dynamic auto, Session 2's "Will it trunk?" again. At HQ this never comes up: every desk port has been switchport mode access since Session 2.

Three ways to learn a secure address

MethodCommandSurvives a reload?
Static (manually configured)switchport port-security mac-address macYes, once the configuration is saved
DynamicNone: the switch learns the address of whatever is plugged inNo: it's forgotten after a reload, and whenever the link goes down (unplug the PC and the port learns whatever comes next)
Sticky (dynamically learned, kept)switchport port-security mac-address stickyYes, once the running configuration is saved: the learned address is written into it

The default maximum is one address per port; switchport port-security maximum raises it. The highest value allowed depends on the switch.

HQ's choices

Trunks, port-channels, S3 G0/1NoneLinks between devices HQ controls; a violation there would cut off a whole switch. Trunk port security is beyond this course.

Aging

Secure addresses can be set to expire, so a port can be reused without anyone deleting the old address by hand. switchport port-security aging time sets the time, and aging type picks how it counts: absolute (deleted after the time, whatever happens) or inactivity (deleted only after the device has been silent that long).

Illustration A shared hot desk where a different laptop sits every day. HQ's desks are sticky, so HQ doesn't use aging.
A hot-desk port · ten minutes of silence frees it
Switch(config)# interface f0/7 Switch(config-if)# switchport mode access Switch(config-if)# switchport port-security Switch(config-if)# switchport port-security aging time 10 Switch(config-if)# switchport port-security aging type inactivity Switch(config-if)# end Switch# show port-security interface f0/7 Port Security : Enabled Port Status : Secure-up Violation Mode : Shutdown Aging Time : 10 mins Aging Type : Inactivity SecureStatic Address Aging : Disabled ...

Aging and sticky answer opposite needs: sticky keeps a desk's PC forever, aging lets the desk forget. Don't combine them.

Module 11.1

Violations and err-disabled ports

A violation happens when a frame arrives from a MAC address that isn't secure on the port, and the port already has its maximum. What the switch does next is the violation mode.

In every mode, frames from the unknown MAC are dropped. The modes differ in what else happens.

ModeKnown device's trafficSyslog messageViolation counterPort err-disabled
shutdown (default)Stops too: the whole port goes downYesIncrementsYes, until shutdown then no shutdown
restrictKeeps flowingYesIncrementsNo
protectKeeps flowingNoNoNo

Protect is the least secure, because nobody ever finds out. Restrict is the middle choice, and it's why SRV1 uses it:

S3 · SRV1 restricts instead of shutting
S3# show port-security interface f0/2 Port Security : Enabled Port Status : Secure-up Violation Mode : Restrict Aging Time : 0 mins Aging Type : Absolute SecureStatic Address Aging : Disabled Maximum MAC Addresses : 1 Total MAC Addresses : 1 Configured MAC Addresses : 0 Sticky MAC Addresses : 1 Last Source Address:Vlan : 0001.64a2.0100:20 Security Violation Count : 0

Under restrict, a stranger on SRV1's port would be dropped and logged, the counter would go up, and the port would stay Secure-up, still serving web and DNS.

Module 11.3

DHCP snooping

Port security alone can stop the simplest DHCP starvation, where each request comes from a new source MAC. It can't stop a tool that keeps one real source MAC and puts made-up addresses inside the DHCP message, and it does nothing against a rogue server. DHCP snooping does.

DHCP snooping sorts every port into two kinds:

TrustedUntrusted (the default)
Which portsThe ones that lead toward the real DHCP server: uplinks and trunks to devices the network team controlsEvery access port, and anything else
DHCP server messages (OFFER, ACK)AllowedDropped: no device here should be answering DHCP
Client requestsAllowedAllowed, up to a rate limit

As leases pass through, the switch records each client on an untrusted port in its DHCP snooping binding table: the MAC address, the IP address it was given, the VLAN and the port. Dynamic ARP Inspection depends on that table.

Four steps: ip dhcp snooping globally; ip dhcp snooping trust on the trusted ports; ip dhcp snooping limit rate on the untrusted ones; and ip dhcp snooping vlan for the VLANs to protect. Snooping does nothing in a VLAN that isn't listed.

HQ's trusted ports

SwitchTrustedWhy
S1Po2 (to D1), Po1 (to S2)R1's replies come back through D1's relay
S2Po3 (to D1), Po1 (to S1)The same, from S2's side
S3G0/1 (to R2)R2 is Shipping's DHCP server
  • Po1 is trusted at both ends. Normally S2's end is blocking, but if Po3 failed, S2's clients would get their replies through S1, over Po1. An untrusted Po1 would break DHCP exactly when the backup path is needed.
  • Trust goes on the port-channel, never on its member ports one by one. A bundle is configured as one interface (Session 5).
  • Every edge port stays untrusted (the default), with a rate limit of 6 DHCP packets a second: plenty for one PC, far below what a starvation tool sends. Over the limit, the port is err-disabled (Reason dhcp-rate-limit in show interfaces status err-disabled). Trusted ports have no limit.

The option 82 line Not on Module 11's list, but needed on real switches. By default a snooping switch adds a tag (DHCP option 82) to each client request, saying which switch and port it came from, and leaves the relay-address field at zero. D1's relay and R2's server treat that combination as suspicious and drop the request, so every new lease would fail. no ip dhcp snooping information option on the three access switches stops the tag, so D1, R1 and R2 need no change.

Then every DHCP client renews, so the switches watch a full exchange and record a binding: PC-C and PC-D at HQ, PC-B at Shipping.

PC-C, PC-D and PC-B · renew under snooping
C:\> ipconfig /release C:\> ipconfig /renew

What snooping doesn't cover: DHCPv6 and router advertisements. PC-B's SLAAC and stateless DHCPv6, and Session 7's stray-router warning, are untouched. The IPv6 equivalents (RA Guard, DHCPv6 Guard) are beyond this course.

Module 11.4

Dynamic ARP Inspection

DAI checks every ARP message that arrives on an untrusted port against the DHCP snooping binding table. If the IP-to-MAC pairing in the ARP message isn't in the table, the message is dropped and logged. A forged "the gateway is at my MAC", like Session 8's, is dropped before any host sees it, in every VLAN where DAI runs.

  • DAI needs DHCP snooping. The binding table is its list of who really has which address. Enable snooping first, on the same VLANs.
  • Trust the same ports for ARP as for DHCP: uplinks toward other switches and the gateway trusted, access ports untrusted.
  • It also rate-limits ARP on untrusted ports, and err-disables a port that goes over.
  • Optional extra checks with ip arp inspection validate: the source MAC, the destination MAC, and invalid IP addresses. Only one validate line is kept, so all the checks you want go on the same line.

VLAN 30 only

  • Every VLAN 30 host leases its address, so every one has a binding.
  • VLAN 10 has PC-A, static all term, with no binding: DAI would drop every ARP it sends. Allowing a static host needs an ARP ACL, which is beyond this course.
  • Shipping's VLAN 20 has SRV1 and S3's own address, both static, so S3 gets no DAI. VLAN 99 has no hosts.
  • The trunks are trusted for DAI as for snooping: D1's SVI, 192.168.30.1, is static too, and its ARP replies arrive over Po3 (or Po1).
S2 · DAI on VLAN 30 (S1 is the same, trusting Po2 and Po1)
S2# configure terminal S2(config)# ip arp inspection vlan 30 S2(config)# ip arp inspection validate src-mac dst-mac ip ! D1's SVI (192.168.30.1) is static, so it has no binding. Its ARPs arrive on the trunks. S2(config)# interface port-channel 3 S2(config-if)# ip arp inspection trust S2(config-if)# interface port-channel 1 S2(config-if)# ip arp inspection trust S2(config-if)# end S2# copy running-config startup-config
  • validate takes all its checks on one line. A second validate line replaces the first. The checks: src-mac (the Ethernet source matches the ARP sender), dst-mac (the Ethernet destination matches the ARP target, on replies) and ip (no 0.0.0.0, broadcast or multicast addresses in the ARP body).
  • DAI rate-limits ARP too: 15 packets a second by default on untrusted ports, then err-disable. HQ keeps the default.
  • S1 gets DAI on VLAN 30 although no live S1 port is in VLAN 30, so the day one is unparked, it's covered.

What DAI stops. No stranger can reach VLAN 30 any more: F0/11 sticks to PC-D, and the rest are parked. So the attack would have to come from PC-D itself, a legitimate PC with malware on it, sending gratuitous ARPs that say "192.168.30.1 is at my MAC". PC-D's MAC is the allowed one, so port security passes it.

S2 · the forged ARP, dropped
%SW_DAI-4-DHCP_SNOOPING_DENY: 1 Invalid ARPs (Res) on Fa0/11, vlan 30.([0090.2b5d.0030/192.168.30.1/ffff.ffff.ffff/192.168.30.1/...])
  • Reading the log: the bracket is sender MAC / sender IP / target MAC / target IP. The sender MAC is PC-D's real one, but S2's binding says that MAC on F0/11 is 192.168.30.10, not .30.1, so the reply is dropped and no other host ever sees it.
  • The layering lesson. Port security asks "is this the right MAC?" and says yes. DAI asks "is this MAC telling the truth about its IP?" and says no. Each stops what the other can't.
  • DAI doesn't drop every gratuitous ARP, only the ones that fail the check. PC-D announcing its own real address is valid and passes.
  • Session 8's own ARP attack, from S1 F0/5 in VLAN 10, is closed by parking, not DAI: VLAN 10 has none.

Module 11.5

PortFast and BPDU Guard

Two features, always used together on access ports. PortFast puts a host port straight into forwarding, skipping the wait while STP checks for loops. BPDU Guard err-disables that port the moment a BPDU arrives on it, because a port with only a host on it should never hear one.

Session 4 callback Session 4 showed these commands as syntax, and explained why PortFast on a link to another switch can cause a loop. Here they go on for real, on host ports only.
S2 · PortFast and BPDU Guard on every edge port (S1 is the same; S3 uses its own range)
S2# configure terminal S2(config)# interface range f0/1 - 22 S2(config-if-range)# spanning-tree portfast %Warning: portfast should only be enabled on ports connected to a single host. Connecting hubs, concentrators, switches, bridges, etc... to this interface when portfast is enabled, can cause temporary bridging loops. Use with CAUTION %Portfast will be configured in 22 interfaces due to the range command but will only have effect when the interfaces are in a non-trunking mode. S2(config-if-range)# spanning-tree bpduguard enable S2(config-if-range)# end S2# copy running-config startup-config
  • Never on Po1–Po3, their member ports, or S3 G0/1. The range simply leaves them out.
  • The warning is normal. IOS reminds you that PortFast on a port with a switch behind it can cause a loop. That's exactly what BPDU Guard guards against.

The other way, which Session 4 also printed. HQ doesn't use it, but it gives the same protection: portfast default covers every port in access mode, and portfast bpduguard default covers every port running PortFast (not "every access port", as NetAcad's slide puts it).

The global alternative
S2(config)# spanning-tree portfast default S2(config)# spanning-tree portfast bpduguard default

Recovery, once the small switch is gone and PC-D is plugged straight back in:

S2 · bring the desk back
S2# configure terminal S2(config)# interface f0/11 S2(config-if)# shutdown S2(config-if)# no shutdown S2(config-if)# end
  • Read the Reason column. Two features can err-disable a desk port: bpduguard (a BPDU arrived) and psecure-violation (a second MAC arrived). Which fires first depends on what the device sends first. Either way the desk is cut off until someone looks, and the Reason column says why.
  • Session 8's fake root would meet the same fate on any desk port. The election it won in Session 8 never happens: no root bridge at a desk.
  • Automatic recovery (beyond this course): errdisable recovery cause bpduguard re-enables the port on a timer. NetAcad's slide gives the cause as psecure_violation, which is wrong: that would recover port-security shutdowns (and is spelled psecure-violation). HQ doesn't use automatic recovery: a desk that keeps re-enabling keeps letting the same device back on.

CDP off on the desk ports

Session 8 showed what CDP gives away to anyone on a desk port, and said HQ would turn it off there in this session. The trunks keep it.

S1 · CDP off on every edge port (S2 is the same; S3 keeps it on G0/1)
S1# configure terminal S1(config)# interface range f0/1 - 22 S1(config-if-range)# no cdp enable S1(config-if-range)# end S1# copy running-config startup-config
S1 · only the links between switches still speak CDP
S1# show cdp interface FastEthernet0/23 is up, line protocol is up Encapsulation ARPA Sending CDP packets every 60 seconds Holdtime is 180 seconds FastEthernet0/24 is up, line protocol is up Encapsulation ARPA Sending CDP packets every 60 seconds Holdtime is 180 seconds GigabitEthernet0/1 is up, line protocol is up Encapsulation ARPA Sending CDP packets every 60 seconds Holdtime is 180 seconds GigabitEthernet0/2 is up, line protocol is up Encapsulation ARPA Sending CDP packets every 60 seconds Holdtime is 180 seconds
  • Only the four inter-switch cables remain: Po1's two members to S2 and Po2's two to D1. CDP runs per physical port, never on the port-channel.
  • The payoff: a desk port no longer hands S1's management address, model and IOS version to whoever plugs in. show cdp neighbors still shows S2 and D1, and the native VLAN mismatch warning still works on every trunk.
  • LLDP: nothing to do. It's off by default on Catalyst switches.

Watch for this

Common Module 11 mistakes

Most Module 11 faults are a feature switched on but not pointed anywhere, or the trust setting on the wrong side of a link.

1 · Snooping on, but no VLAN

ip dhcp snooping alone does nothing. Without ip dhcp snooping vlan, nothing is filtered and the binding table stays empty. show ip dhcp snooping shows an empty VLAN list.

2 · The uplink left untrusted

The real server's OFFERs are dropped like a rogue's: new clients get 169.254. Check the trusted list in show ip dhcp snooping.

3 · Trust on the member ports

On a bundle, trust goes on the port-channel. show ip dhcp snooping should list Port-channel3, not GigabitEthernet0/1.

4 · Option 82 left on (real switches)

Relayed HQ clients and Shipping's clients get no lease. show ip dhcp snooping says Insertion of option 82 is enabled.

5 · DAI before the clients renewed

PC-D has no binding yet, so DAI drops its ARPs and it loses its gateway. Order: snooping, renew, check the bindings, then DAI.

6 · DAI on a VLAN with static hosts

On VLAN 10, every ARP from PC-A would be dropped. The drop counter in show ip arp inspection statistics climbs.

7 · validate on three lines

Only the last one counts. show ip arp inspection vlan 30 shows two of the three checks disabled.

8 · Sticky, never saved

After a reload, the desk sticks to whatever is plugged in next. The sticky line is in show running-config but not show startup-config.

9 · A new PC at a sticky desk

The port err-disables for a legitimate swap. Remove the old sticky line, then shutdown and no shutdown.

10 · BPDU Guard on an uplink

Typed on a trunk or port-channel, it err-disables the link at D1's first BPDU, and the switch loses its root port. Reason bpduguard in show interfaces status err-disabled.

11 · Checking PortFast with the summary

show spanning-tree summary shows only the global defaults. Per-port PortFast is in show spanning-tree interface … detail.

12 · A rate limit on the trusted uplink

Under load the uplink err-disables, and the whole switch loses DHCP. Trusted ports should show unlimited.

Ticket #141-09 · Priority: normal · From: Front Desk

The new hire's laptop arrived today. We unplugged the old PC at PC-C's old desk and plugged the laptop in where it was. Nothing works, and the little light next to the laptop's network port is off. The old PC worked fine there yesterday.

One way to break it down

Applied

Worked examples

Think it through before you expand the answer.

Port security

Why did it err-disable?

A desk port has port security with the defaults plus mac-address sticky. Someone unplugs the PC and plugs in a laptop. The port goes err-disabled. Why, and what are two ways the administrator could have prepared for a legitimate swap?

Show answer

The defaults are a maximum of 1 and violation mode shutdown. Sticky kept the PC's MAC even while the cable was out, so the laptop's MAC was a second address: a violation, and the port shut. For a legitimate swap, either remove the old sticky address first (no switchport port-security mac-address sticky old-mac), or allow a second address with maximum 2. After the fact, remove the old address, then shutdown and no shutdown. (Without sticky, the swap would have worked: a dynamic secure address is forgotten when the link goes down.)

Sticky

Gone after a reload

An administrator turns on mac-address sticky, sees the addresses in show running-config, and reloads the switch the next morning. The addresses are gone. What was missed?

Show answer

copy running-config startup-config. Sticky addresses go into the running configuration; only saving it puts them in NVRAM.

Snooping

Nobody gets a lease

After DHCP snooping goes on, every client in a VLAN gets 169.254 addresses. Snooping is enabled globally and for the VLAN. What should you check first?

Show answer

Which ports are trusted. If the uplink toward the real DHCP server isn't trusted, snooping drops the server's OFFERs on it, exactly as it would a rogue server's. show ip dhcp snooping lists the trusted interfaces.

DAI

PC-A can't reach its gateway

Someone turns DAI on for VLAN 10 too. PC-A, with its static address, can no longer reach anything off its subnet, but PC-C, on DHCP, is fine. Why?

Show answer

DAI checks ARP against the DHCP snooping binding table, and PC-A never got a lease, so it has no binding. Its ARP messages are dropped as invalid. That's why HQ runs DAI only where every host uses DHCP. (Static hosts can be allowed with ARP ACLs, which are beyond this course.)

Trust

The server port

SRV1, the DNS and web server, is on S3 F0/2. It's a server the network team controls. Should its port be trusted for DHCP snooping?

Show answer

No. Trust is about the direction of the real DHCP server, and SRV1 isn't it; R2 is. If SRV1's port were trusted and someone turned on SRV1's own DHCP service by mistake, it would become a rogue server that snooping lets through.

BPDU Guard

Is the uplink at risk?

Someone runs spanning-tree portfast default and spanning-tree portfast bpduguard default. Is the trunk to D1 at risk?

Show answer

No. portfast default applies only to ports in access mode, and the global BPDU Guard applies only to PortFast ports, so trunks are left alone. The risk is the per-interface form: spanning-tree bpduguard enable typed on a trunk or port-channel would err-disable it at the next BPDU from D1.
