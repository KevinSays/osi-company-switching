Module 5.1

Why STP: what a loop does

Redundant links are good: if one cable fails, traffic takes another. But at Layer 2, two paths between the same switches form a loop, and switches flood broadcasts out every port. Without something to stop them, frames go round and round.

CCNA 1 callback In CCNA 1 you learned that every router lowers a packet's TTL (IPv6: hop limit) and drops it at zero, so a routing loop eventually ends. That's a Layer 3 field. An Ethernet frame has no TTL, and a switch never changes anything in it. A frame in a Layer 2 loop never dies.
ProblemWhat happens on our triangle without STP
Broadcast stormPC-A sends one ARP broadcast. S1 floods it toward both S2 and D1. Each of them floods its copy onward, including toward the other, and two copies circle the triangle in opposite directions forever. Every new broadcast adds more. The links fill up and the switches stop coping.
MAC table instabilityS2 learns PC-A's MAC on F0/23 (the copy straight from S1), then on G0/1 (the copy that went round through D1), then on F0/23 again, many times a second. S2 can't decide where PC-A is.
Duplicate framesA unicast to a MAC no switch has learned yet is flooded, so it reaches the destination by both paths. PC-C gets two copies or more.
Multicast tooMulticast is flooded like a broadcast. IPv6 neighbor discovery uses multicast, so IPv6 melts as well.

Spanning Tree Protocol fixes all four the same way. It logically blocks just enough ports that there's exactly one active path between any two switches, so the cabling is a loop but the forwarding is a tree. If an active link fails, STP unblocks a port to restore a path. Two hallways are safer than one, as long as nobody walks in circles.

See it: the storm (instructor demo) Your instructor will show a real broadcast storm on the projector, from a throwaway copy of today's finished network, in Simulation mode. Spanning Tree is turned off for VLAN 10 on all three switches (no spanning-tree vlan 10), PC-A clears its ARP cache and pings PC-C, and the ARP broadcast is stepped through: out of S1 both ways, copies crossing at S2 and D1, copies coming back to S1, and an event list that never ends. In Packet Tracer, only VLAN 10 melts: PC-D in VLAN 30 can still reach its gateway, because PVST+ runs a separate tree for each VLAN, and only one was turned off. On real switches, don't count on it: VLAN 10's storm fills the shared trunks and D1's CPU (its Vlan10 SVI receives every broadcast), so the other VLANs suffer too.

Don't try this in your own file. A storm can make Packet Tracer stop responding. If you ever find a no spanning-tree vlan line in a config, the fix is spanning-tree vlan with the same VLAN number (here, spanning-tree vlan 10) on every switch, then clear mac address-table dynamic.

Module 5.2

How STP decides: the election

STP is an election followed by a seating plan. Every switch starts out claiming to be the boss, the root bridge, and sends BPDUs (bridge protocol data units) every 2 seconds saying so. The best claim wins, and then every port is given a job based on how close it is to the winner.

Step 1 · The root bridge: lowest bridge ID wins

A switch's bridge ID (BID) is its priority followed by its MAC address. Lower wins at every step: lowest priority, and if that ties, lowest MAC.

  • Default priority is 32768, and the switch adds the VLAN number to it (the extended system ID). So in VLAN 10 every switch shows 32778; in VLAN 30, 32798.
  • Out of the box, every priority ties, so the lowest MAC wins. A MAC address is basically a serial number, so the default root is luck.
  • The same switch wins in every VLAN by default, because each switch uses the same MAC for all of them.
  • Priorities can only be set in multiples of 4096 (0, 4096, 8192, … 61440). The other 12 bits of the field are the VLAN number.

Step 2 · One root port on every other switch

Each non-root switch picks the one port with the lowest root path cost: the total of the port costs on the way to the root, counting the cost of each port that receives the root's BPDUs. On our switches, a Gigabit port costs 4 and a Fast Ethernet port costs 19.

Step 3 · One designated port on every link

Each link gets one designated port: the end on the switch that's closer to the root (lower root path cost). Every port on the root bridge is designated, and so is every port facing a host.

Step 4 · Whatever's left blocks

Any port that's neither a root port nor a designated port is an alternate port, and it blocks. It still listens to BPDUs, so it can take over if something fails.

Ties, in order When two candidates have the same root path cost, STP compares, in order: the lower sender bridge ID, then the lower sender port ID (port priority, default 128, then port number). Notice sender: it's the neighbor's numbers that count, not your own. With one cable between each pair of switches, the bridge ID always settles it. The port ID only matters when two cables run between the same two switches.

Work it out by hand

In this example S2 is root. Every one of S2's ports is designated. Then:

  • D1's root port: straight to S2 through G1/0/3 costs 4. Through S1 costs 4 + 19 = 23. Root port: G1/0/3.
  • S1's root port: straight to S2 through F0/23 costs 19. Through D1 costs 4 (S1 G0/1) + 4 (D1 G1/0/3) = 8. Root port: G0/1. Two Gigabit hops beat one Fast Ethernet hop.
  • Designated ports: S2's ends of both its links (it's root), and D1 G1/0/1 on the D1–S1 link, because S1's end is its root port.
  • Left over: S1 F0/23. Alternate, blocking.

Design the root: you choose the boss

The root should be the switch at the center of traffic, not the one with the lowest serial number. At HQ that's D1: it holds every gateway, so every frame that leaves a VLAN goes there anyway. S1 is the backup.

D1 · become root for every VLAN on the triangle
D1# configure terminal ! ! The distribution switch, where the gateways live, becomes root for every VLAN the triangle carries. D1(config)# spanning-tree vlan 10,30,99,900 root primary D1(config)# end D1# copy running-config startup-config
S1 · the backup root
S1# configure terminal ! ! S1 takes over if D1 fails. S1(config)# spanning-tree vlan 10,30,99,900 root secondary S1(config)# end S1# copy running-config startup-config

S2: nothing. It keeps the default, 32768. After each command the tree is recalculated, and ports may sit in LSN or LRN for up to 50 seconds. Pings across HQ can drop while that happens. Wait before you check.

  • Why these four VLANs: 10, 30, 99 and 900 are carried by all three trunks, so they're the VLANs with a loop. VLAN 900 has no hosts, but it's on every trunk, so it has a tree like the others. VLANs 1 and 999 have no active ports, so there's no tree to run.
  • VLAN 40 joins the list in Session 10, when it's created.

Predict every port before you look

D1 is 24576 (24586 in VLAN 10), S1 is 28672 (28682), S2 is 32768 (32778).

  • Root: D1, on priority alone. Both its ports are designated.
  • S1's root port: G0/1, cost 4. The other way, F0/23 through S2, costs 19 + 4 = 23.
  • S2's root port: G0/1, cost 4. The same reasoning.
  • The S1–S2 link needs one designated port. Both switches advertise a cost of 4: a tie. Next tie-breaker, bridge ID: S1's 28682 beats S2's 32778. S1 F0/23 is designated. That's exactly what root secondary bought you.
  • Left over: S2 F0/23. Alternate, blocking.

Module 5.2

Port states and timers

A port doesn't jump straight from blocking to forwarding. If it did, it could open a loop for a moment before every switch agreed on the new tree. It goes through two waiting states first.

StateBPDUsLearns MACsForwards dataHow long
BlockingReceives onlyNoNoUntil STP decides otherwise
ListeningSends and receivesNoNoForward delay, 15 s
LearningSends and receivesYesNoForward delay, 15 s
ForwardingSends and receivesYesYesSteady state
DisabledNoneNoNoThe port is shut down

Learning fills the MAC table before the port forwards, so it doesn't start by flooding everything.

TimerDefaultWhat it does
Hello time2 sHow often the root sends BPDUs (the other switches pass them on)
Forward delay15 sTime spent in listening, and again in learning
Max age20 sHow long a switch keeps a port's last BPDU without hearing a new one before it decides that path is gone

The timers are set on the root, and every other switch uses the root's values, because they're carried in its BPDUs. Don't change them in this course.

EventTime to forwardingWhy
A new link comes up, or a switch sees its own link failabout 30 sListening 15 + learning 15
A switch has to work out that the best path is gone somewhere elseup to about 50 sMax age 20 (waiting for the old information to expire) + 15 + 15

Thirty to fifty seconds of silence is a long time on a network. That's the number Rapid PVST+ fixes next session. Packet Tracer may run these timers faster than real switches do; learn the real numbers.

Watch a failover: cut S1's uplink

Last session's single point of failure was S1's link to D1. Cut it, and watch the blocked port open.

Set up first: on S2, have show spanning-tree vlan 10 ready to repeat (press up-arrow). On PC-A, start ping -t 192.168.10.1, a ping that runs until you stop it with Ctrl+C. Its timeouts show the outage.

D1 · cut the link to S1
D1# configure terminal D1(config)# interface g1/0/1 D1(config-if)# shutdown D1(config-if)# end

What happens, in order (real 802.1D timing)

  1. S1 loses its root port. Its only other trunk, F0/23, is a designated port: S1 sends BPDUs there but hears none, because S2's end is blocking. So S1 announces that it is now the root.
  2. S2 ignores S1's claim at first. It's worse than what S2 last heard on that port (root = D1). S2 keeps the old, better information until it ages out: max age, 20 s.
  3. After about 20 s, S2 makes F0/23 the designated port for that link, because S2 knows a better root (D1, through its own G0/1) than the one S1 is claiming. S2 starts passing D1's BPDUs to S1.
  4. S1 learns that D1 is reachable through S2, makes F0/23 its root port (cost 19 + 4 = 23), and stops claiming to be root.
  5. S2 F0/23 goes listening (15 s), then learning (15 s), then forwarding. That's the port that unblocks.
  6. Total: about 50 seconds with no path for S1's hosts. PC-A's ping shows it.

Module 5.3

The evolution of STP

Original STP is slow, and it runs one tree for the whole network. Every later version fixes one or both of those.

VersionWhoTreesSpeedIn one line
STPIEEE 802.1D (1998 and earlier)One for all VLANsSlow, 30–50 sThe original algorithm
PVST+CiscoOne per VLANSlowCisco's per-VLAN version of 802.1D STP. Today's default. Adds Cisco extras such as PortFast and BPDU guard.
RSTPIEEE 802.1wOneFast, often under a secondThe fast-converging successor to STP. Same election, new states and roles, and a quick handshake instead of waiting on timers.
Rapid PVST+CiscoOne per VLANFastCisco's per-VLAN version of RSTP. Next session.
MSTPIEEE 802.1sOne per instance; you map groups of VLANs to eachFastThe IEEE standard that cuts the number of trees: many VLANs share one
MSTCiscoSame as MSTPFastCisco's implementation of MSTP
A naming trap The 2004 edition of the 802.1D standard is RSTP: it replaced the original STP algorithm with 802.1w's. So when this course says "802.1D" or "STP", it means the original, slow algorithm from the 1998 and earlier editions. Some materials describe 802.1D-2004 as just "an updated STP"; it's more than that.

  • Alternate port: a backup path to the root through a different switch. That's S2 F0/23 today: PVST+ on our switches already uses the name.
  • Backup port: a second port onto a shared segment the switch already has a designated port on, which in practice means two ports into the same hub. Rare now.
  • Edge port: a port facing a host. It's RSTP's name for what PortFast does.

Module 5.3

PortFast and BPDU guard

Know them today; you'll apply them across the network in Session 9, with the rest of switch security. Don't configure them in today's file.

  • PortFast: a host port skips listening and learning and forwards the moment the link comes up. Without it, a PC that boots waits 30 seconds before its port forwards, which can be long enough for its DHCP client to give up. Host ports only: on a link to another switch it can open a loop.
  • BPDU guard: if a PortFast port ever receives a BPDU, meaning someone plugged a switch into a desk port, the switch shuts that port down (err-disabled). It stays down until an administrator brings it back.
S1 · syntax only, don't apply today
S1# configure terminal S1(config)# interface range f0/1 - 20 ! ! Access ports only. Never on F0/23-24 or G0/1-2. S1(config-if-range)# spanning-tree portfast S1(config-if-range)# spanning-tree bpduguard enable S1(config-if-range)# end
S1 · or on every access port at once
S1(config)# spanning-tree portfast default S1(config)# spanning-tree portfast bpduguard default
S1 · check, and recover a port BPDU guard shut down
S1# show spanning-tree interface f0/1 portfast S1# show interfaces status err-disabled ! ! After removing whatever sent the BPDU: S1(config)# interface f0/1 S1(config-if)# shutdown S1(config-if)# no shutdown
  • IOS warns you when you turn PortFast on, reminding you it belongs only on ports to a single host.
  • The default forms apply only to ports in access mode, so a trunk is safe from them. Still: host ports only.
  • Newer IOS versions spell it spanning-tree portfast edge. Packet Tracer's 2960 uses the form above.

Module 5.3

Alternatives to STP

STP's price: a whole link sits idle, failover takes time, and the result depends on settings people forget. Two ways to need it less:

AlternativeThe ideaIn this course
EtherChannel (Module 6)Bundle parallel links into one logical link. STP sees one port, so no member blocks, and the bandwidth adds up. If one member fails, the bundle just shrinks.Next session. Our triangle stays a triangle, though: one bundle will still block.
Layer 3 (routed) linksMake the links between switches routed (no switchport). Routing protocols can use every path, and IP packets have a TTL. STP shrinks to inside each access switch.D1's link to R1 is already one: no STP runs on it. The catch: a VLAN can no longer stretch across two access switches.
Coming up in CCNA 3 Network design in layers (access, distribution, core), and when to route instead of switch between them. Today's triangle is the access and distribution layers in miniature.

Watch for this

Common Module 5 mistakes

Most STP mistakes are reading mistakes, not typing ones.

1 · Root on only one VLAN

spanning-tree vlan 10 root primary makes D1 root for VLAN 10 only. VLANs 30, 99 and 900 keep their random default root. show spanning-tree vlan 30: the Root ID address isn't D1's. Fix: re-enter it with the whole list, 10,30,99,900.

2 · Primary and secondary swapped

root primary typed on S1 and root secondary on D1. show spanning-tree vlan 10 on D1 has no This bridge is the root. Fix: swap them.

3 · A priority that isn't a multiple of 4096

spanning-tree vlan 10 priority 25000 is rejected, and IOS lists the values it accepts. Use 24576, or another multiple of 4096.

4 · Native VLAN mismatch on the new trunk

D1 G1/0/3's native VLAN left at 1: CDP NATIVE_VLAN_MISMATCH messages on both ends, and show interfaces trunk shows different native VLANs. Fix: switchport trunk native vlan 900 on the end that's wrong.

5 · One end never became a trunk

On D1, switchport mode trunk was rejected because the encapsulation line was skipped, and nobody noticed. show interfaces trunk on D1: Gi1/0/3 is missing. Fix: switchport trunk encapsulation dot1q first, then trunk mode.

6 · Forgot no shutdown

Both new ports were parked and shut. A shut port doesn't appear in the STP output at all. Fix: no shutdown on both ends.

7 · A VLAN left off the new trunk

Allowed list typed as 10,99,900. VLAN 30 still works, through S1, but it has no backup path, and show spanning-tree vlan 30 on D1 has no Gi1/0/3. Fix: switchport trunk allowed vlan add 30.

8 · Checking too soon

Ports show LSN or LRN, and pings fail. That's not a fault: wait 30 to 50 seconds after any change.

9 · Reading the wrong block

"S1's priority is 24586": that's the Root ID block, which is D1's. S1's own priority is in the Bridge ID block. And the Cost column is each port's cost, not the path cost.

10 · Using your own port ID to break a tie

When two links to the same switch tie, it's the sender's port ID that decides, not the receiving switch's.

Recurring segment

The Ticket

Turn it into steps before you open Packet Tracer.

Ticket #141-04 · Priority: low · From: the crew chief

Someone in the network meeting asked why, now that the new S2–D1 cable is in, the cable between S1 and S2 "shows orange and never carries anything." Is it broken? Should we replace it? Also, if D1 goes down, which switch takes over, and does that mean we still have internet?

One way to break it down
  1. "Orange and never carries anything": an amber link light in Packet Tracer usually means STP is blocking that port. Check it: show spanning-tree vlan 10 on S2. If F0/23 shows Altn BLK, the cable is fine. It's the backup path, on purpose.
  2. Explain why it's that link: D1 is root, S1 and S2 both reach it directly for a cost of 4, and the S1–S2 link is the long way round. On that link, S1 wins the tie because it's root secondary, so S2's end blocks.
  3. Prove it's a working backup: shut D1 G1/0/1 and watch S2 F0/23 go to forwarding. Then restore it.
  4. "If D1 goes down, which switch takes over?" S1 becomes the STP root, because it's root secondary. show spanning-tree vlan 10 on S1 would say This bridge is the root.
  5. "Do we still have internet?" No. STP root and gateway are different jobs. S1 can't route, so with D1 down, every HQ VLAN loses its gateway. That's a job for a first-hop redundancy protocol, which arrives in Session 7.

Applied

Worked examples

Think it through before you expand the answer.

Bridge ID

Which number is the priority?

On S1, show spanning-tree vlan 30 shows Bridge ID Priority 28702 (priority 28672 sys-id-ext 30). A classmate says S1's priority is 28702. Are they right, and what would S1 show in VLAN 99?

Show answer

The configured priority is 28672, the value root secondary set. The 28702 on the line is that plus the VLAN number (the extended system ID), 30. In VLAN 99 the same switch shows 28771 (28672 + 99). The VLAN number never decides an election: every switch adds the same number in the same VLAN.

Path cost

The long way round

D1 is root. What is S1's root path cost through its G0/1 port, and through its F0/23 port? Which becomes its root port?

Show answer

Through G0/1, straight to D1: 4 (one Gigabit port, S1's own). Through F0/23: 19 + 4 = 23 (S1's Fast Ethernet port, then S2's Gigabit port into D1). Lower wins, so G0/1 is the root port. Costs are counted on the ports that receive the root's BPDUs on the way in, so D1's own ports add nothing.

Tie-breakers

Why S2, and not S1?

After the design, S1 and S2 both have a root path cost of 4. So why does S2's end of the F0/23 link block, and not S1's?

Show answer

The link needs one designated port. Both ends advertise the same cost (4), so the next tie-breaker is the bridge ID. S1's is 28682 (root secondary), S2's is 32778 (the default). S1 is lower, so S1 F0/23 is designated, and S2 F0/23 is left over: alternate, blocking. Without root secondary, both would be 32778, and the lower MAC would decide.

The root macro

The boss who didn't fight back

D1 was made root with root primary last week. Today a classmate types spanning-tree vlan 10 priority 20480 on S2. What happens in VLAN 10?

Show answer

S2 becomes the root for VLAN 10. root primary is a one-time macro: when it ran, it set D1 to 24576 and saved that as a plain priority 24576 line. It doesn't watch the network afterwards. 20480 is lower than 24576, so S2 wins. The fix is to set D1 lower again (for example, 16384), or remove S2's line.

Traceroute vs STP

The path tracert can't see

After the design, PC-A runs tracert 192.168.10.11 (PC-C). It shows one hop. Does that prove the frames go straight across F0/23?

Show answer

No. Traceroute only shows routers (Layer 3 hops). PC-A and PC-C are in the same VLAN, so there are none. With S2 F0/23 blocking, the frames actually go S1 → D1 → S2. To prove the Layer 2 path, use show spanning-tree (which ports forward) and show mac address-table (which port each switch learned PC-A on).
