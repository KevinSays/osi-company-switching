EtherChannel: The Odd Pair

Last session, every backup cable at HQ sat idle, blocked by Spanning Tree, and a failover took most of a minute. This session fixes both. Every hallway gets a second cable, and each pair is bundled into one wide corridor that STP treats as a single link. Then the whole triangle switches to Rapid PVST+, which recovers in about a second. The catch: a bundle forms only when both ends agree, and the odd pair that doesn't match never forms at all.

Module 6.1

Why bundle: two cables, one link

The obvious way to get more bandwidth between two switches is a second cable. On its own, that doesn't work: two cables between the same two switches are a loop, so Spanning Tree blocks one of them. You pay for two links and use one.

EtherChannel (Cisco's name for link aggregation) groups up to eight parallel Ethernet links into one logical link, called a port channel. The switch, and Spanning Tree with it, sees one interface, Port-channel1, instead of two or more physical ports. Nothing is blocked inside the bundle, because to STP there's nothing to block.

AdvantageWhat it means
More bandwidthTwo Gigabit links bundled give up to 2 Gb/s between the switches, with the cables and ports you already have.
RedundancyIf one member fails, the bundle keeps running on the rest. STP keeps the port-channel, so no root port is lost. (On a real switch the bundle's cost rises; see STP sees bundles.)
Load sharingTraffic is spread across the members. Each flow uses one member, chosen by a hash of addresses (for example source and destination MAC or IP), so one conversation never exceeds one cable's speed.
One interface to configureTrunk mode, the native VLAN and the allowed list are set once, on the port-channel, and apply to every member.
Session 4 callback HQ's S1–S2 cable was Altn BLK all through Session 4, carrying nothing until a failure. A bundle doesn't change that: STP will still block one of HQ's three links, as STP sees bundles shows. What changes is that each link is now two cables wide, and losing one cable no longer causes an outage: the bundle just shrinks.

Module 6.1

The rules for members

A bundle is only as healthy as its least-matching member. Every physical port in it must agree with the others on:

Must matchWhy
Speed and duplexThe members must be interchangeable. You can't bundle a Fast Ethernet port with a Gigabit one, and every member must have the same duplex setting (in practice, full duplex).
Switchport modeAll access ports in the same VLAN, or all trunks.
VLAN settingsOn trunks: the same native VLAN and the same allowed list. On access ports: the same access VLAN.
NegotiationThe same protocol, PAgP or LACP, on both ends, in modes that agree (next section).
  • Up to eight active members per bundle. LACP can hold up to eight more in standby, ready to replace a failed member.
  • Configure the port-channel, not the members. Settings applied to the port-channel interface are copied to its members. Settings typed on one member, such as a different allowed list, make it disagree with the rest, and it gets suspended from the bundle.
  • Same numbers aren't required. The port-channel number is local: S1's Po2 could be D1's Po7. HQ uses matching numbers so the diagrams are readable.

Module 6.1

PAgP and LACP: how a bundle forms

The two ends have to agree that a bundle exists, which ports are in it, and that every member matches. They can be told by hand, or they can negotiate with a protocol.

Module 6.2

Configure EtherChannel

Two steps on each switch: put the member ports into a channel group with a mode, which creates the port-channel interface; then configure the port-channel interface itself. On a trunk bundle, the trunk settings go on the port-channel.

Here are HQ's bundles. Each switch lists its member ports with interface range, gives them the trunk settings so they match each other, puts them in a group with channel-group, and then states the trunk settings once more on the port-channel, which is where they're managed from now on.

Po1: S1–S2, LACP (S1 active, S2 passive)

Po3: S2–D1, PAgP (D1 desirable, S2 auto)

D1 · Po3 to S2
D1(config)# interface range g1/0/3 - 4 D1(config-if-range)# description Po3 member to S2 D1(config-if-range)# switchport trunk encapsulation dot1q D1(config-if-range)# switchport mode trunk D1(config-if-range)# switchport trunk native vlan 900 D1(config-if-range)# switchport trunk allowed vlan 10,30,99,900 D1(config-if-range)# switchport nonegotiate D1(config-if-range)# no switchport access vlan D1(config-if-range)# channel-group 3 mode desirable D1(config-if-range)# exit D1(config)# interface port-channel 3 D1(config-if)# description Po3 to S2 G0/1-2 (PAgP) D1(config-if)# switchport trunk encapsulation dot1q D1(config-if)# switchport mode trunk D1(config-if)# switchport trunk native vlan 900 D1(config-if)# switchport trunk allowed vlan 10,30,99,900 D1(config-if)# switchport nonegotiate
S2 · Po3 to D1
S2(config)# interface range g0/1 - 2 S2(config-if-range)# description Po3 member to D1 S2(config-if-range)# switchport mode trunk S2(config-if-range)# switchport trunk native vlan 900 S2(config-if-range)# switchport trunk allowed vlan 10,30,99,900 S2(config-if-range)# switchport nonegotiate S2(config-if-range)# no switchport access vlan S2(config-if-range)# channel-group 3 mode auto S2(config-if-range)# exit S2(config)# interface port-channel 3 S2(config-if)# description Po3 to D1 G1/0/3-4 (PAgP) S2(config-if)# switchport mode trunk S2(config-if)# switchport trunk native vlan 900 S2(config-if)# switchport trunk allowed vlan 10,30,99,900 S2(config-if)# switchport nonegotiate
  • The mode keyword picks the protocol. active and passive mean LACP; desirable and auto mean PAgP.
  • Why the trunk lines appear twice. Members must match before they'll bundle, and each new cable starts as a parked access port in VLAN 999, so the member lines make them match once. After that, change settings on the port-channel only: a setting on the port-channel is copied to every member, but a setting typed on one member changes only that member, which then no longer matches and drops out.
  • nonegotiate still belongs. It turns off DTP, which negotiates trunking. LACP and PAgP negotiate bundling, and keep working.
  • Group numbers are local. HQ keeps them matched so the diagram is readable, which is why S2 has a Po1 and a Po3 but no Po2.
Changing a live link into a bundle HQ's links were already carrying traffic, so the order of work matters. 1. Shut every member, on both ends, before typing anything else; a half-built bundle is when loops happen. 2. Make the members match: the parked cable copies the live one. 3. channel-group on the members, then the port-channel settings. Don't create an empty port-channel first. 4. Both ends finished, then no shutdown on both. 5. Wait for the bundle and Spanning Tree to settle before starting the next one. (Don't reach for default interface to "clean" a port: it turns the port back on.)
How a flow is shared The switch picks one member for each flow, by a hash of MAC or IP addresses, not one per frame. So a single PC-A to PC-C transfer uses one of Po2's cables and one of Po3's. Each bundle's 2 Gb/s is the total for all flows together, not the speed of any one conversation.

Module 6.3

Troubleshoot EtherChannel

A bundle fails in one of two ways: it never forms, or it forms with some members left out. Both show up in show etherchannel summary.

THREAT LEVEL: BUNDLE

CASE FILE D-05

The Odd Pair

Two ends of a bundle that don't match. One speaks PAgP and the other LACP, both wait politely for the other to ask, or one member carries a different VLAN list from its partners. The cables are fine and the lights are green, but the corridor never opens, or opens one cable narrower than it should.

Tell: in show etherchannel summary, a port-channel that isn't (SU), members flagged (I) stand-alone or (s) suspended instead of (P), or a Protocol column that differs from the far end's.

See also: Which pairs form a bundle · Will it bundle?

Debrief Both ends of a bundle show their member ports up/up, and pings across work. Why might the bundle still be broken? (If the bundle didn't form, the members can still come up as separate links, and Spanning Tree blocks all but one. Traffic flows over a single cable, so pings work, but there's no extra bandwidth and no bundle failover. Only the EtherChannel flags show it.)

Most odd pairs don't stop pings. When a bundle fails to form, its members usually come up as ordinary separate trunks, STP sees two parallel links and blocks one, and the network keeps working on a single cable. The tells are the flags, and the physical port names reappearing in show spanning-tree and show interfaces trunk.

Fixing a mode safely

Don't change a working bundle's mode while its members are up. Shut them, take them out of the group, put them back with the right mode, and bring them up. Changing between PAgP and LACP is refused unless the port leaves its group first.

D1 · Po3 back to desirable
D1# configure terminal D1(config)# interface range g1/0/3 - 4 D1(config-if-range)# shutdown D1(config-if-range)# no channel-group D1(config-if-range)# channel-group 3 mode desirable D1(config-if-range)# no shutdown D1(config-if-range)# end D1# show etherchannel summary

The method in four steps: show etherchannel summary on both ends; read the port-channel and member configuration; fix; check the summary again.

How Spanning Tree sees the bundles

To STP, each bundle is one port with one cost. HQ is still a triangle, now of three port-channels, so STP still has to block one of them.

A bundle's cost

A port-channel's STP cost comes from its combined bandwidth, so a bundle is "shorter" than one of its cables.

LinkBandwidthCost (short method)
One Gigabit cable1 Gb/s4
Po2, Po3: 2 × Gigabit2 Gb/s3
One Fast Ethernet cable100 Mb/s19
Po1: 2 × Fast Ethernet200 Mb/s12 on a real switch; Packet Tracer may show 9

The election, again

  1. Root: D1, on priority. Both its port-channels are designated.
  2. S1's root port: Po2, cost 3. The other way, Po1 then Po3, costs 9 + 3 = 12 (or 15 with a cost of 12).
  3. S2's root port: Po3, cost 3, by the same reasoning.
  4. Po1 needs one designated end. Both switches advertise 3: a tie. S1's bridge ID, 28682, beats S2's 32778, so S1's end is designated.
  5. Left over: S2's Po1. Alternate, blocking. Exactly where Session 4 blocked, one level up.
S2 · the tree, still PVST+ (Packet Tracer costs)
S2# show spanning-tree vlan 10 VLAN0010 Spanning tree enabled protocol ieee Root ID Priority 24586 Address 00D0.97CC.00D1 Cost 3 Port 29(Port-channel3) ... Interface Role Sts Cost Prio.Nbr Type ---------------- ---- --- --------- -------- -------------------------------- Fa0/1 Desg FWD 19 128.1 P2p Po1 Altn BLK 9 128.27 P2p Po3 Root FWD 3 128.29 P2p
  • The physical members are gone from STP. No Fa0/23, Fa0/24, Gi0/1 or Gi0/2 lines: STP sees Po1, Po2 and Po3.
  • One cable down, no outage. If one member fails, the bundle keeps running on the other, so no root port is lost. The bundle's bandwidth halves, and on a real switch its cost rises with it, which can move which end of Po1 blocks, without stopping any traffic.
  • The port-channel numbers (in the Prio.Nbr column and the Root ID Port line), and the Type, can differ in Packet Tracer.

CCNA v1.1 supplement

Rapid PVST+

Session 4's PVST+ took 30 to 50 seconds to recover, because a port had to wait out timers before it could forward. Rapid PVST+ is Cisco's per-VLAN version of RSTP (IEEE 802.1w). It runs the same election and finds the same tree, but switches confirm changes with each other directly instead of waiting, so most failovers take about a second.

Session 4 callback The evolution of STP table listed RSTP and Rapid PVST+, and previewed RSTP's port states. Here they arrive.

What stays the same

  • The election. Lowest bridge ID is root; root ports, designated ports and the tie-breakers work exactly as in Session 4. HQ's roles don't change.
  • Per VLAN. Like PVST+, Rapid PVST+ runs a separate tree for each VLAN, with the same priorities.

What changes

PVST+ (802.1D)Rapid PVST+ (802.1w)
Port statesBlocking, listening, learning, forwarding, disabledDiscarding, learning, forwarding
Backup rolesA blocked port (Cisco shows it as Altn) must wait out listening and learning before it can take overAlternate: a ready-made backup path to the root. Backup: a second port on a shared segment.
BPDUsOnly the root originates them; others relayEvery switch sends its own every 2 seconds, so a dead neighbor is noticed after three missed hellos (about 6 seconds), not 20
Moving to forwardingWait 15 s listening plus 15 s learningOn point-to-point links, a quick proposal/agreement handshake; an alternate port takes over at once when the root port fails
Typical failover30–50 secondsAbout a second, or less

Link types

The fast handshake only works where exactly two switches share a link. Rapid PVST+ works out each port's link type from its duplex:

Link typeWhat it isFast transition?
Point-to-point (P2p)A full-duplex link between two switches. Every HQ trunk and bundle.Yes
Shared (Shr)A half-duplex link, such as one through a hubNo: falls back to 802.1D timers
Edge (Edge)A port facing a host, set with PortFast. It forwards at once and never takes part in the handshake.Forwards immediately

Turning it on

D1 · then the same on S1, then S2
D1# configure terminal D1(config)# spanning-tree mode rapid-pvst D1(config)# end D1# copy running-config startup-config
  • The order doesn't change the result. RSTP is backward compatible: while one neighbor still runs PVST+, the port facing it falls back to the old rules, so a half-converted network works, just slowly.
  • Each change restarts STP on that switch, so expect a short blip. One switch at a time, root first: D1, S1, S2.
  • Then, on each switch, clear spanning-tree detected-protocols, so ports that heard old-style BPDUs during the changeover check again.

Failover, now

Fail S2's uplink (shut Po3 on D1). S2 has lost its root port, but it already has an alternate, Po1. RSTP makes Po1 the root port and forwarding at once, a local decision with no handshake and no timer. S2's traffic now goes S2 → Po1 → S1 → Po2 → D1. On a real switch, PC-C's ping loses at most a reply or so. Under PVST+, the same failure would have cost about 30 seconds.

The catch: host ports still wait RSTP skips the timers only when someone at the other end can say "agreed". Another switch can; a PC can't. When Po3 comes back, S2 briefly makes its other ports safe before switching back, and that includes PC-C's and PC-D's ports. On a real switch they wait out the old 15 + 15 seconds, unless they're edge ports. That's what PortFast does under Rapid PVST+, and HQ's host ports get it in Session 9. Packet Tracer may not show the wait.

Common Module 6 mistakes

Almost every EtherChannel fault is a mismatch: between the two ends, or between one member and the rest.

1 · Two polite ends

auto + auto, or passive + passive. Both would bundle if asked; neither asks. One end must be desirable or active.

2 · Mixing the protocols

PAgP on one end and LACP on the other never bundles. Compare the Protocol column at both ends.

3 · Settings on a member

Once bundled, configure the port-channel. A change typed on one member makes it the odd one out, and it's suspended.

4 · Forgetting the parked cable

The new cable starts as an access port in VLAN 999. If it isn't made a matching trunk, it joins as (s).

5 · Building without shutting first

A half-built bundle, one end grouped and the other not, is when loops and err-disabled ports happen on real switches.

6 · Reading BLK as broken

A healthy Po1(SU) can be Altn BLK in STP, and still shows BLK under Rapid PVST+. EtherChannel and STP answer different questions.

Recurring segment

The Ticket

Turn it into steps before you open the answer.

Ticket #141-05 · Priority: low · From: the crew chief

We paid for a second cable between S2 and D1 last week. The monitoring screen still shows S2's uplink at 1 Gb/s. Did the new cable even get plugged in? And is it true we're still "wasting" a link somewhere?

One way to break it down
  1. "Still 1 Gb/s" suggests the bundle didn't form, or formed with one member. On S2 and on D1, show etherchannel summary: Po3 should be (SU) with both members (P).
  2. If it's (SD) with members (I), compare the Protocol column and the modes at both ends: the design is D1 desirable, S2 auto. Two auto ends, or one end on LACP, is the odd pair.
  3. If one member is (s), find what differs: show running-config interface for each member. Fix it on the port-channel, not the member.
  4. Confirm: show interfaces port-channel 3 shows BW 2,000,000 Kbit.
  5. "Wasting a link": yes, on purpose. show spanning-tree vlan 10 on S2 shows Po1 Altn BLK. A triangle is a loop, so STP blocks one side. It's the backup path, and it takes over in about a second now.

Worked examples

Think it through before you expand the answer.

Modes

Will it bundle?

S1 G0/1–2 are channel-group 2 mode passive. D1 G1/0/1–2 are channel-group 2 mode auto. What happens?

Show answer

No bundle. passive is LACP and auto is PAgP: different protocols. (Even with the same protocol, passive + passive or auto + auto would fail, because neither end asks.) The members come up stand-alone, (I), and STP blocks one of them.

Cost

Why is the bundle "shorter"?

Before today, S1 reached D1 for a cost of 4. Now it's 3. Nothing got closer. Why?

Show answer

STP cost comes from bandwidth. One Gigabit link is 4; a 2 Gb/s bundle is 3. The port-channel is one STP port with the combined bandwidth, so the root path cost drops.

Suspended

One cable, half a bundle

show etherchannel summary on S2 shows Po3(SU) PAgP Gig0/1(P) Gig0/2(s). What does that mean, and where do you fix it?

Show answer

The bundle is up on Gig0/1 only. Gig0/2 is suspended: it doesn't match its partner, typically a different allowed VLAN list or native VLAN typed on that one port. Fix it by setting the trunk settings on interface port-channel 3, which copies them to both members.

STP

Healthy, and blocked

A classmate says Po1 is broken because show spanning-tree on S2 shows it Altn BLK. show etherchannel summary shows Po1(SU) with both members (P). Who's right?

Show answer

Nothing is broken. The bundle is healthy (SU, both P), and STP is blocking it on purpose, because the three port-channels form a loop. S2 reaches the root more cheaply through Po3, and S1 wins the tie on Po1.

Rapid PVST+

Why so fast?

With Rapid PVST+, shutting Po3 costs PC-C about a second instead of 30. What does S2 do differently?

Show answer

S2 already knows a backup path to the root: Po1, its alternate port. When its root port fails, RSTP makes the alternate the new root port and forwards at once. There are no listening and learning timers to wait out.
